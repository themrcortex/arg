## ترمینال تعاملی

ترمینال وب از PTY واقعی استفاده می‌کند تا برنامه‌های تعاملی و shell رفتار متعارف داشته باشند. چند tab مستقل قابل بازکردن و نام‌گذاری‌اند. تعویض صفحهٔ پنل، state ترمینال را در همان نشست نگه می‌دارد تا هنگام بازگشت، tabها از بین نروند؛ refresh کامل مرورگر ممکن است WebSocket را قطع کند.

## ابزار هر Tab

- ساخت و بستن tab، تغییر عنوان و اتصال مجدد به session.
- Copy با انتخاب متن و Paste با Clipboard؛ در مرورگر/موبایل ممکن است اجازهٔ Clipboard لازم باشد.
- `Ctrl+Shift+C` برای Copy و `Ctrl+Shift+V` برای Paste در محیط‌هایی که مرورگر این میانبر را به صفحه می‌دهد. کلیدهای مرورگر یا سیستم‌عامل ممکن است اولویت داشته باشند.
- پاک‌کردن viewport فقط صفحه را تمیز می‌کند و history پردازش سرور را پاک نمی‌کند.
- تغییر اندازهٔ پنجره و اسکرول؛ wheel داخل ناحیهٔ ترمینال باید به scrollback ترمینال برسد.

## ترمینال Root

Root Terminal برای عملیات با اثر کامل روی میزبان است و ممکن است داده یا سیستم‌عامل را تخریب کند. ایجاد آن نیازمند نقش مدیر، تأیید هشدار و احراز هویت مجدد است. مجوز کوتاه‌عمر و یک‌بارمصرف است و به حساب/نشست جاری محدود می‌شود. نشست‌های Root را پس از استفاده ببند و فرمان‌های کپی‌شده را قبل از Paste بازبینی کن.

ترمینال root محدودیت تعداد tab ندارد، اما هر shell process منابع می‌گیرد. تعداد زیاد نشست باز را مدیریت و نشست بدون استفاده را ببند. هیچ دستوری را صرفاً به‌دلیل نمایش در راهنما اجرا نکن.

## قطع ارتباط

اگر WebSocket قطع شد، پیام اتصال مجدد و علت قابل مشاهده را بررسی کن. وضعیت shell ممکن است همچنان روی سرور زنده باشد یا به‌دلیل timeout بسته شده باشد. ابتدا فهرست process و سرویس را از نشست SSH دوم بررسی کن؛ تکرار سریع دکمهٔ اتصال می‌تواند tabهای اضافه بسازد.

## کار با تب‌ها و اتصال

صفحهٔ ترمینال بعد از ورود ممکن است تب بازشدهٔ قبلی را نگه دارد؛ برای تب تازه دکمهٔ **+** را بزن. هر تب نشست مستقل PTY دارد؛ عنوان را با کلیک/rename تغییر بده تا محیط تولید و staging قاطی نشود. بستن تب اتصال همان نشست را پایان می‌دهد؛ جابه‌جایی به صفحهٔ دیگر الزاماً نشست را نمی‌بندد. اتصال مجدد را وقتی وضعیت اتصال قطع است اجرا کن و قبل از ارسال فرمان بررسی کن prompt تازه آمده باشد.

Clipboard ابزار از clipboard سیستم/مرورگر استفاده می‌کند و مجوز مرورگر لازم است. Paste ممکن است فرمان را بی‌درنگ وارد یا اجرا کند؛ قبل از Ctrl+Shift+V محتوای کلیپ‌بورد را کنترل کن. برای کپی، متن را انتخاب کن و از دکمه/میانبر راهنما استفاده کن؛ کپی‌کردن رمز یا private key به clipboard خطر افشا دارد. اسکرول را در ناحیهٔ ترمینال انجام بده؛ وقتی shell در حال اجرای برنامهٔ تعاملی است، کلیدهای جهت‌دار همان برنامه را کنترل می‌کنند.

### Terminal عادی و Root

ترمینال معمولی تحت مجوز حساب سرویس/کاربر تعیین‌شده اجرا می‌شود؛ اجرای `sudo` به policy سیستم وابسته است و UI آن را تضمین نمی‌کند. برای کار root یک تب جداگانهٔ **Terminal Root** باز کن. صفحه هشدار می‌دهد که فرمان‌ها می‌توانند فایل‌ها و سرویس‌های سیستم را بدون محدودیت تخریب کنند؛ فقط در صورت نیاز واقعی تأیید کن. Root Terminal را برای کارهای روزانه، مرور فایل یا اجرای دستور از راه‌دور استفاده نکن.

### روال امن نمونه

برای مشاهده وضعیت nginx، فرمان read-only مناسب را اجرا کن و خروجی را بررسی کن. برای تغییر فایل ابتدا backup بگیر، سپس فایل را با editor امن تغییر بده، `nginx -t` اجرا کن و فقط در صورت موفقیت Reload کن. فرمان destructive مثل `rm -rf`, `mkfs`, `iptables -F` یا pipe-to-shell را از ترمینال اجرا نکن مگر اثر و rollback را دقیقاً می‌دانی. خروجی ترمینال می‌تواند Token یا مسیر حساس داشته باشد؛ آن را قبل از share پاکسازی کن.

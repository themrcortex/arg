# مدیریت Laravel

Laravel Runner به هر کارت اپلیکیشن با قالب Laravel اضافه می‌شود. این ابزار release فعال را بررسی می‌کند، فایل محیط و داده‌های `storage` را میان releaseها نگه می‌دارد، وابستگی‌ها را با Composer و lockfile نصب می‌کند و فقط فرمان‌های مشخص Artisan را اجرا می‌کند.

## پیش‌نیازها

1. در صفحهٔ **اپلیکیشن‌ها**، یک اپ با قالب Laravel ثبت کن.
2. از همان کارت یک منبع Git، ZIP یا پوشهٔ VPS را به‌صورت release مستقر کن.
3. مخزن باید `artisan`، `composer.json`، `composer.lock` و `public/index.php` داشته باشد. فایل `composer.lock` برای نصب تکرارپذیر الزامی است.
4. نسخهٔ PHP CLI انتخاب‌شده باید نصب باشد. اگر Composer پیش‌نیازهای PHP یا افزونه‌ای را پیدا نکند، خروجی عملیات علت را نشان می‌دهد.

تا قبل از اولین deploy، Runner مسیر فعالی برای بازرسی ندارد. برای جلوگیری از نمایش وضعیت ساختگی، کارت به‌جای «آماده» خطای نبود release می‌دهد.

## بررسی وضعیت

روی **بررسی** بزن. ARG فایل‌های Laravel و Composer، مسیر `public`، constraint نسخهٔ PHP و افزونه‌های `ext-*` را می‌خواند. فقط نام کلیدهای محیط نشان داده می‌شود؛ مقدارهای `.env` از API یا UI خوانده نمی‌شوند.

وضعیت‌ها:

- **وابستگی‌ها نصب نیست:** lockfile یا `vendor/autoload.php` وجود ندارد.
- **تنظیم محیط لازم است:** APP_KEY یا اتصال دیتابیس در فایل خصوصی کامل نیست.
- **آماده:** اجزای بررسی‌شده پیدا شده‌اند. پس از فعال‌کردن وب، سلامت HTTP و سرویس‌ها جداگانه بررسی می‌شود.

## تنظیم فایل محیط

متغیرهایی مثل `APP_ENV`, `APP_URL`, `DB_CONNECTION`, `DB_HOST`, `DB_DATABASE`, `DB_USERNAME` و `DB_PASSWORD` را در فرم وارد کن و **ذخیرهٔ متغیرها** را بزن. مقدار خانهٔ خالی تغییر نمی‌کند؛ بنابراین برای حفظ رمز موجود، آن را دوباره وارد نکن. مقادیر در فایل `shared/.env` با mode خصوصی `0600` ذخیره می‌شوند و در پاسخ API بازگردانده نمی‌شوند. هنگام فعال‌سازی PHP-FPM، ACL خواندن فقط برای کاربر سرویس وب روی این فایل تنظیم می‌شود؛ مقدارها همچنان از پنل یا API قابل خواندن نیستند.

دکمهٔ **ساخت APP_KEY** فقط وقتی APP_KEY خالی است فعال می‌شود. کلید با منبع تصادفی امن ساخته و مستقیم در فایل ذخیره می‌شود. جایگزینی کلید موجود عمداً از این دکمه ممکن نیست؛ تغییر APP_KEY می‌تواند داده‌های رمزگذاری‌شدهٔ Laravel را غیرقابل‌خواندن کند.

فایل `shared/.env` و پوشهٔ `shared/storage` خارج از releaseها قرار دارند. در deployهای بعدی، release جدید به همان فایل و پوشه پیوند می‌خورد. نسخهٔ قبلی دادهٔ محیط را جایگزین نمی‌کند. از قرار دادن رمزها در مخزن یا ZIP پرهیز کن؛ اگر فایل `.env` همراه منبع باشد، اولین release آن را به فضای پایدار منتقل می‌کند.

## نصب Composer

اگر `vendor/autoload.php` موجود نیست، **نصب وابستگی از روی lockfile** را انتخاب و تأیید کن. ARG فرمان ثابت `composer install` را با `composer.lock` اجرا می‌کند و این گزینه‌ها را اعمال می‌کند:

- `--no-dev` برای حذف dependencyهای توسعه از نصب تولیدی
- `--no-scripts` و `--no-plugins` برای جلوگیری از اجرای کد وابستگی‌ها در فرایند نصب
- مهلت ۲۰ دقیقه و سقف خروجی ذخیره‌شده
- حداقل فضای آزاد بررسی‌شدهٔ ۵۱۲ MiB

این کار به شبکهٔ عمومی بسته‌ها وصل می‌شود. اگر نصب شکست بخورد، خروجی خام Composer پنهان می‌ماند چون آدرس یا اعتبارنامهٔ مخزن خصوصی می‌تواند در آن باشد. پیام خطا، نسخهٔ PHP، افزونه‌ها و دسترسی شبکه را بررسی کن.

## عملیات Artisan

فرمان دلخواه قابل واردکردن نیست. Runner فقط موارد زیر را می‌پذیرد:

| عملیات | کاربرد | تغییر داده |
| --- | --- | --- |
| اطلاعات Laravel (`about`) | نمایش اطلاعات برنامه و محیط | ندارد |
| وضعیت migration | نمایش migrationهای اجراشده و pending | ندارد |
| پاک‌سازی cache | `optimize:clear` | cache برنامه پاک می‌شود |
| ساخت cache تنظیمات | `config:cache` | فایل cache تنظیمات بازسازی می‌شود |
| ساخت cache مسیر | `route:cache` | مسیرها cache می‌شوند؛ routeهای Closure ممکن است این کار را ناممکن کنند |
| ساخت cache view | `view:cache` | viewهای Blade کامپایل می‌شوند |
| راه‌اندازی مجدد Queue | `queue:restart` | workerهای متصل به cache در پایان job جاری restart می‌شوند |
| اجرای migration | `migrate --force` | ساختار یا دادهٔ DB ممکن است تغییر کند |

برای migration، پنجرهٔ تأیید خطر نمایش داده می‌شود. backup دیتابیس را پیش از ادامه بررسی کن. Rollback release فقط کد را برمی‌گرداند و migration دیتابیس را معکوس نمی‌کند. خروجی عملیات در تاریخچه می‌ماند، اندازه‌اش محدود است و الگوهای رایج رمز و مقدارهای موجود در `.env` از آن پالایش می‌شوند. اجرای هم‌زمان دو عملیات روی یک اپ جلوگیری می‌شود.

## اتصال وب و سرویس‌های پس‌زمینه

بعد از آماده‌شدن release و `.env`، **ساخت و فعال‌کردن سایت** یک pool مجزای PHP-FPM برای همان اپ، socket اختصاصی و فایل Nginx با نام `arg-app-<شناسه>` می‌سازد. ریشهٔ وب فقط `public` است؛ PHP فقط از مسیر ثابت `public/index.php` اجرا می‌شود و فایل‌های مخفی و پسوندهای حساس مسدودند. `nginx -t` و آزمون کانفیگ PHP-FPM پیش از فعال‌سازی اجرا می‌شوند. اگر آزمون یا reload شکست بخورد، فایل تنظیم قبلی بازگردانده می‌شود. دامنهٔ تکراری با سایت‌های ثبت‌شدهٔ Nginx رد می‌شود. اگر تنظیم یکپارچهٔ فایروال سایت فعال باشد، هنگام روشن‌کردن، قوانین HTTP/HTTPS از همان مسیر Nginx هماهنگ می‌شوند.

برای دسترسی فایل‌ها از ACL استفاده می‌شود: Nginx/PHP-FPM به release، `.env` و storage همان اپ دسترسی محدود می‌گیرند. اگر `setfacl` نصب نباشد عملیات وب متوقف می‌شود؛ بستهٔ سیستم `acl` را نصب کن و دوباره بزن. پیمایش ACL روی storage برای جلوگیری از بار سنگین روی حداکثر ۲۰٬۰۰۰ مورد محدود است. pool با `pm=ondemand` و سقف ۸ worker ساخته می‌شود و PHP به مسیر همین اپ محدود است. چند pool هنوز با کاربر سیستمی مشترک `www-data` اجرا می‌شوند؛ این جداسازی کامل کاربر سیستم‌عامل برای هر مشتری نیست.

خاموش‌کردن وب فقط سایت را از Nginx خارج می‌کند و release، `.env` و فایل‌ها را حذف نمی‌کند. صدور SSL از ابزار فعلی همان سایت در صفحهٔ Nginx انجام می‌شود؛ کانفیگ اولیه فقط HTTP/80 می‌سازد.

برای **Queue Worker**، **Scheduler**، **Horizon**، **Reverb** و **Octane** کنترل systemd جداگانه وجود دارد؛ فعال‌سازی Horizon، Reverb و Octane به نصب پکیج مربوط در release فعال وابسته است. Horizon و Queue Worker جداگانه را هم‌زمان برای یک اپ اجرا نکن؛ ARG این تداخل را رد می‌کند. Reverb و Octane فقط روی loopback سرور و پورت جداگانهٔ همان اپ گوش می‌دهند و مستقیم به اینترنت عمومی باز نمی‌شوند. وقتی Octane را برای سایت روشن فعال کنی، ARG کانفیگ Nginx همان سایت را از PHP-FPM به پورت loopback Octane تغییر می‌دهد. هنگام خاموش‌کردن، ابتدا Nginx را به PHP-FPM برمی‌گرداند و بعد Octane را متوقف می‌کند. شکست تغییر Nginx یا سرویس گزارش می‌شود و سامانه تا جای ممکن حالت قبلی را بازمی‌گرداند.

فرمان سرویس‌ها ثابت است و فرم، shell دلخواه نمی‌پذیرد. هر unit با PHP انتخاب‌شده، کاربر سیستم `arg`، راه‌اندازی مجدد پس از خروج ناموفق و لاگ در journal سیستم اجرا می‌شود. وضعیت از systemd دوباره خوانده می‌شود. بعد از deploy یا rollback، کانفیگ وب و سرویس‌های فعال refresh می‌شوند. اگر deploy نتواند سرویس نسخهٔ تازه را آماده کند، اشاره‌گر کد به release قبلی برمی‌گردد؛ در rollback دستی نیز در صورت شکست، بازگردانی اشاره‌گر و refresh سرویس‌ها تلاش می‌شود. Rollback کد، تغییرهای دیتابیس را معکوس نمی‌کند.

دکمهٔ **ساخت دیتابیس و کاربر** یک دیتابیس با نام مشخص و حسابی جدا با مجوز محدود به همان دیتابیس ایجاد می‌کند. MySQL باید نصب و روشن باشد و مدیر یک بار از صفحهٔ MySQL با رمز پنل، دسترسی مدیریتی را فعال کرده باشد. ARG رمز تصادفی را فقط در فایل خصوصی `shared/.env` نگه می‌دارد و آن را به مرورگر یا Audit نمی‌فرستد. اگر مقادیر دیتابیس از قبل وجود داشته باشند، بازنویسی نمی‌شوند. اگر نوشتن `.env` شکست بخورد، ARG پاک‌کردن همان دیتابیس و کاربری را که در این عملیات ساخته تلاش می‌کند؛ اگر پاک‌سازی کامل نشود، پیام خطا آن را مشخص می‌کند.

سایت ساخته‌شده در ابتدا روی HTTP/80 است. برای HTTPS از ابزار SSL همان سایت در صفحهٔ Nginx استفاده کن. کانفیگ تولیدشده در همان صفحه قابل مشاهده است و مالکیت ARG را حفظ می‌کند.

## API و داده

- `GET /api/apps/{id}/laravel`: بررسی release و نام کلیدهای محیط.
- `GET /api/apps/{id}/laravel/operations`: تاریخچهٔ عملیات.
- `POST /api/apps/{id}/laravel/operations`: اجرای عملیات مجاز با بدنهٔ `{ "action": "migrate", "confirmed": true }`.
- `PUT /api/apps/{id}/laravel/environment`: ثبت map از نام متغیر به مقدار؛ پاسخ، مقدارها را شامل نمی‌شود.
- `POST /api/apps/{id}/laravel/environment`: تولید APP_KEY فقط در صورت خالی‌بودن.
- `GET /api/apps/{id}/laravel/web`: وضعیت سایت، PHP-FPM، Queue، Scheduler، Horizon، Reverb و Octane به‌همراه پورت‌های loopback.
- `POST /api/apps/{id}/laravel/web`: `{ "enabled": true|false }` برای ساخت/فعال‌سازی یا خاموش‌کردن سایت.
- `POST /api/apps/{id}/laravel/services`: `{ "service": "queue"|"scheduler"|"horizon"|"reverb"|"octane", "enabled": true|false }`.
- `POST /api/apps/{id}/laravel/database`: `{ "confirmed": true }` برای ساخت دیتابیس و کاربر محدود اپ پس از فعال‌کردن مجوز MySQL.

همهٔ عملیات به نقش مدیر و Origin معتبر نیاز دارند و در Audit ثبت می‌شوند. جدول `laravel_operations` تاریخچه را نگه می‌دارد؛ Job در حال اجرا پس از راه‌اندازی مجدد پنل با وضعیت `interrupted` مشخص می‌شود.

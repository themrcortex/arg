## اتصال پنل

TLS را برای استفادهٔ عمومی فعال کن. نصب بدون SSL مجاز است، اما HTTP عمومی نام کاربری، رمز و Cookie را در مسیر رمزنگاری‌نشده منتقل می‌کند. از SSH tunnel یا شبکهٔ خصوصی استفاده کن تا certificate معتبر فعال شود. نصب‌کننده TLS را اجباری نمی‌کند و در صورت شکست ادامه می‌دهد؛ این فقط امکان‌پذیری نصب را حفظ می‌کند و خطر HTTP را رفع نمی‌کند.

## حساب و نشست

از رمز بلند و منحصر‌به‌فرد استفاده کن؛ کد راه‌اندازی/رمز reset را در کانال عمومی نفرست. از دستگاه مشترک خروج کن و نشست ناشناس را لغو کن. Root Terminal به بازتأیید مدیر نیاز دارد؛ با آن فقط فرمان‌های لازم را اجرا کن.

## کلیدهای S3 و TLS

- Secret Access Key از API به Frontend بازگردانده نمی‌شود.
- فایل credential روی سرور باید فقط توسط root قابل خواندن باشد.
- کلید TLS خصوصی در Git، ticket، log، query string یا screenshot قرار نگیرد.
- پیش از ثبت endpoint خصوصی S3، آدرس و مقصد DNS را بررسی کن؛ endpoint داخلی می‌تواند مسیر SSRF ایجاد کند.

## Firewall و شبکه

Firewall ارائه‌دهنده مستقل از UFW است. قبل از تغییر policy، SSH و پنل را allow و نشست دوم را برقرار کن. UFW را در زمان اتصال SSH به‌صورت کورکورانه فعال نکن. حتی پورت محافظت‌شده در ARG، ACL بیرونی یا route دیتاسنتر را کنترل نمی‌کند.

## عملیات پرخطر

حذف فایل، دیتابیس، Volume Docker، Bucket، Unmount، firewall، package purge، reboot و rollback اثر متفاوت دارند. متن تأیید را بخوان. برای سرویس تولیدی یک plan بازگشت داشته باش. `sudo` و دسترسی Docker می‌تواند کنترل گستردهٔ میزبان بدهد.

## جمع‌آوری اطلاعات پشتیبانی

در logهای systemd، خطای API، endpoint یا username ممکن است دیده شود. قبل از انتشار log، hostname، IP عمومی/خصوصی، credential، مسیرهای شخصی، domain مشتری و SQL data را پاک کن. ARG telemetry اجباری برای مستندات عمومی ندارد.

## محدودیت تضمین

ARG ابزار مدیریتی است؛ صحت کانفیگ سفارشی، سازگاری برنامه، امنیت کد سایت یا backup را تضمین نمی‌کند. Security review سند ریسک/بازبینی است، نه گواهی ممیزی مستقل یا penetration test.

## کاربران و نقش‌ها

فهرست کاربران را با username، نقش و وضعیت فعال بخوان. Admin می‌تواند عملیات مدیریتی حساس اجرا کند؛ نقش viewer فقط امکانات مجاز خواندن را دارد. پیش از تغییر Role، مطمئن شو حداقل یک مدیر قابل‌دسترسی باقی می‌ماند. غیرفعال‌کردن یا حذف حساب می‌تواند نشست فعلی همان کاربر را باطل کند.

## Audit log و محدودیت تفسیر

گزارش عملیات Actor، نوع عمل، زمان، نتیجه و جزئیات امن را ثبت می‌کند. از فیلتر زمانی برای یافتن رخداد استفاده و جزئیات را باز کن. Audit جایگزین Nginx access/error log، خروجی APT یا journalctl نیست؛ هر منبع پاسخ سؤال متفاوتی می‌دهد. Credential نباید در event/log قرار گیرد. خروجی را پیش از اشتراک‌گذاری برای IP، نام فایل، username و توکن احتمالی بررسی کن.

نمونهٔ بررسی تغییر فایروال: بازهٔ زمانی را دور زمان تغییر بگذار، actor و event مدیریت Rule را باز کن، سپس Rule فعلی UFW را در صفحهٔ Firewall با آن تطبیق بده. رخداد موفق تنها می‌گوید درخواست اجرا شده؛ سلامت دسترسی از خارج را با Probe و اتصال واقعی بررسی کن.

## امنیت TLS و Root

اگر پنل از HTTP عمومی سرو می‌شود، رمز عبور و cookie نشست بین مرورگر و VPS رمزنگاری نمی‌شود. پس از تهیهٔ گواهی، TLS را فعال کن و پورت HTTP پنل را طبق تنظیمات ببند/redirect امن کن؛ وجود گواهی روی Nginx یک سایت به معنی HTTPS بودن خود پنل ARG نیست. Root Terminal و اجرای helper را فقط برای Admin استفاده کن؛ تأیید هویت نشست را با مجوز root اشتباه نگیر. کلید خصوصی TLS، Secret S3، رمز DB و tokenها را در خروجی/اسکرین‌شات پنهان کن.

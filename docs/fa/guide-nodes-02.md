# جفت‌سازی سرورها با دسترسی محدود

## چه چیزهایی لازم است؟

هر دو سمت باید ARG به‌روز داشته باشند. پنل مقصد باید از HTTPS با گواهی قابل‌اعتماد در دسترس Controller باشد. ساعت سیستم، DNS و مسیر شبکهٔ بین دو VPS را هم بررسی کن. لازم نیست پنل مقصد روی IP عمومی باشد اگر از شبکهٔ خصوصی استفاده می‌کنی؛ در این حالت فقط گزینهٔ مخصوص مقصد خصوصی را فعال کن.

## ساخت کد روی مقصد

به **Nodeها ← اجازهٔ مدیریت این سرور** برو. حالت `فقط‌خواندنی` اجازهٔ تغییر سرویس و داده نمی‌دهد. حالت `کامل` برای مدیر مورداعتماد است و دسترسی فضای‌کار و ترمینال را هم می‌دهد. دسترسی کامل به معنی ارسال توکن مرورگر نیست؛ مقصد هر scope را سمت سرور بررسی می‌کند.

کد یک‌بارمصرف بساز، آن را از طریق کانال امن به مدیر Controller بده و همان‌جا وارد کند. کد پنج دقیقه اعتبار دارد و با اولین Pairing مصرف می‌شود. برای تنظیم مقصد، شناسهٔ endpoint را به صورت URL پایه مانند `https://panel.example.net` بده؛ مسیر `/api`، query string یا اطلاعات کاربری داخل URL ننویس.

## ثبت مقصد در Controller

در **Nodeها ← اتصال این پنل به پنل دیگر**، برچسب محلی، Endpoint و کد را وارد کن. برچسب فقط برای همین Controller است. گزینهٔ شبکهٔ خصوصی را تنها برای IPهای private یا نام‌های DNS داخلی روشن کن. آدرس loopback، link-local و metadata حتی با این گزینه مجاز نمی‌شود.

بعد از Pairing، کارت مقصد باید نام عمومی، وضعیت اتصال، سازگاری و سطح دسترسی را نشان دهد. Workspace را از نوار بالا انتخاب کن تا صفحات پنل مقصد باز شوند. پیش از عملیات تغییردهنده، عنوان سرور فعال را دوباره بررسی کن.

## اگر اتصال ساخته نشد

- خطای DNS: از سرور Controller بررسی کن نام مقصد به IP صحیح resolve می‌شود.
- خطای HTTPS: گواهی مقصد باید معتبر و نام آن با Endpoint منطبق باشد؛ redirect به HTTP مجاز نیست.
- کد نامعتبر: کد منقضی یا مصرف‌شده را جایگزین و کد جدید بساز.
- نسخه ناسازگار: هر دو پنل را به‌روز کن و پس از بررسی دسترسی‌ها دوباره جفت‌سازی کن.
- مقصد خصوصی: گزینهٔ شبکهٔ خصوصی باید در Controller فعال باشد؛ این گزینه را برای مقصد عمومی روشن نکن.

لغو اتصال Controller credential را باطل می‌کند، اما فایل و سرویس VPS مقصد را حذف نمی‌کند.

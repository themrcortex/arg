# مدیریت DNS با Cloudflare

این راهنما صفحهٔ **مدیریت DNS** در ARG را توضیح می‌دهد. این صفحه یک Zone در Cloudflare را با Token محدود وصل می‌کند و رکوردها را مستقیماً در همان Zone می‌خواند یا تغییر می‌دهد. تغییر اشتباه می‌تواند دسترسی سایت یا ایمیل را قطع کند؛ پیش از هر تغییر، مقدار فعلی رکورد را از Cloudflare یادداشت کن.

## دسترسی و پیش‌نیازها

- این صفحه فقط برای کاربر **مدیر** ARG نمایش داده می‌شود.
- سرور باید بتواند از طریق HTTPS به Cloudflare API دسترسی خروجی داشته باشد.
- Zone دامنه باید در حسابی باشد که Token به آن دسترسی دارد؛ Zone در این راهنما یعنی دامنهٔ اصلی مانند `example.com`، نه آدرس کامل `https://example.com`.
- برای امنیت، Token را فقط به همان Zone محدود کن و دسترسی‌های `Zone:Read` و `DNS:Edit` را بده. از Global API Key یا Token با دسترسی همهٔ Zoneها استفاده نکن.

برای ساخت Token در Cloudflare، از بخش **My Profile → API Tokens** یک Token سفارشی بساز. جزئیات رسمی در [راهنمای API Tokenهای Cloudflare](https://developers.cloudflare.com/fundamentals/api/get-started/create-token/) آمده است.

## اتصال یک Zone

۱. از منوی ARG، **مدیریت DNS** را باز کن و **اتصال Cloudflare** را بزن.
۲. یک نام محلی برای اتصال وارد کن تا Zoneها در ARG از هم قابل تشخیص باشند.
۳. نام Zone را مثل `example.com` و API Token را وارد کن.
۴. **بررسی و اتصال** را بزن. ARG از Cloudflare می‌خواهد Zone را پیدا کند و دسترسی Token را تأیید کند؛ اگر Zone پیدا نشود یا Token مجوز نداشته باشد، اتصال ذخیره نمی‌شود.

بعد از اتصال، Token دوباره در رابط یا پاسخ API نمایش داده نمی‌شود و ARG آن را به‌صورت رمز‌شده در فایل خصوصی محلی نگه می‌دارد. رمزگذاری Credential روی سرور، جایگزین امن‌سازی خود VPS نیست.

## مشاهدهٔ رکوردها

Zone متصل را انتخاب کن تا رکوردهای آن نمایش داده شوند. ستون‌ها نوع، نام، مقدار، TTL و وضعیت Proxy را نشان می‌دهند. در رابط فعلی فقط صفحهٔ اول API با حداکثر ۱۰۰ رکورد خوانده می‌شود و صفحه‌بندی در UI وجود ندارد؛ بنابراین اگر Zone بیش از ۱۰۰ رکورد دارد، این فهرست کامل نیست و برای مرور کامل از داشبورد Cloudflare استفاده کن.

## ساخت رکورد

از **رکورد جدید** یکی از نوع‌های `A`، `AAAA`، `CNAME`، `MX` یا `TXT` را انتخاب کن. رابط، مقدارها را پیش از ارسال بررسی می‌کند و API نیز رکورد را به Zone انتخاب‌شده محدود می‌کند.

- نام `@` به خود دامنهٔ Zone اشاره دارد؛ برای زیردامنه، نام کامل مثل `www.example.com` را وارد کن. نام رکورد باید داخل Zone انتخابی باشد.
- `A` به IPv4 و `AAAA` به IPv6 معتبر نیاز دارد. مقدار `CNAME` باید نام میزبان باشد.
- رکورد `MX` به مقصد و اولویت نیاز دارد. مقدارهای مرتبط با ایمیل را با مسئول ایمیل هماهنگ کن.
- TTL برابر `1` در Cloudflare یعنی **Automatic**؛ مقدارهای دستی باید بین ۶۰ تا ۸۶۴۰۰ ثانیه باشند.
- Proxy فقط برای `A`، `AAAA` و `CNAME` در رابط قابل انتخاب است؛ برای رکوردهای ایمیل یا `TXT` آن را فعال نکن.

با تأیید ساخت، درخواست مستقیم به Cloudflare فرستاده می‌شود. ARG قبل از آن رکوردها را با DNS عمومی منتشر نمی‌کند و نتیجهٔ انتشار را هم آزمایش نمی‌کند.

## حذف رکورد یا قطع اتصال

حذف رکورد مستقیماً آن را از Zone واقعی Cloudflare پاک می‌کند. رکوردهای `MX` و `TXT` ممکن است برای ایمیل، SPF، DKIM یا DMARC لازم باشند؛ پیش از حذف وابستگی را بررسی کن. رابط فعلی نمایش، ساخت و حذف رکورد را ارائه می‌کند و ویرایش رکورد موجود در آن در دسترس نیست.

**قطع اتصال Cloudflare** فقط Credential ذخیره‌شده در ARG را حذف می‌کند؛ Zone و رکوردهای موجود در Cloudflare را تغییر نمی‌دهد. اگر دسترسی ARG به Token لازم نیست، آن را از Cloudflare هم لغو کن.

## بررسی تغییر و عیب‌یابی

بعد از تغییر، از دستگاهی که ابزار DNS دارد، پاسخ را با پرس‌وجویی مثل `dig A www.example.com` بررسی کن. Resolverها ممکن است تا پایان TTL مقدار قبلی را نگه دارند. این صفحه propagation check، DNS-01 برای صدور گواهی، تغییر Nameserver نزد Registrar یا مدیریت Providerهای دیگر را انجام نمی‌دهد. قابلیت DNS-01 را با SSL خودکار Nginx اشتباه نگیر.

- خطای دسترسی یا Zone: نام Zone و دسترسی `Zone:Read` و `DNS:Edit` Token را بازبینی کن.
- خطای مقدار: نوع رکورد، قالب IP یا hostname، نام داخل Zone، TTL و اولویت `MX` را بررسی کن.
- Timeout یا پاسخ نامشخص: پیش از تکرار ساخت/حذف، داشبورد Cloudflare را باز کن و ببین تغییر قبلی اعمال شده است یا نه.
- پاسخ قدیمی DNS: رکورد را در Cloudflare و سپس چند Resolver بررسی کن؛ نتیجه به Cache و TTL وابسته است.

برای تنظیم `server_name` و SSL در ARG، راهنمای [مدیریت Nginx و سایت‌ها](?page=nginx) را ببین؛ آن صفحه خودش رکورد DNS را تغییر نمی‌دهد.

# کلیدهای SSH و استقرار مخزن خصوصی

این صفحه ساخت کلیدهای Git را در ARG توضیح می‌دهد. کلیدها به سروری تعلق دارند که در انتخاب‌گر فضای‌کار فعال است؛ اگر اپلیکیشن روی Node اجرا می‌شود، ابتدا همان Node را انتخاب کن. در نمای «همهٔ سرورها» مدیریت کلید غیرفعال است.

## Deploy Key در برابر کلید حساب

- **Deploy Key** به یک مخزن GitHub محدود است. برای دریافت کد، دسترسی فقط‌خواندنی کافی است و گزینهٔ دسترسی نوشتن را در GitHub خاموش بگذار.
- **کلید شخصی حساب GitHub** اگر در تنظیمات حساب ثبت شود، از مجوزهای همان حساب پیروی می‌کند و ممکن است به چند مخزن دسترسی داشته باشد. برای سایت‌ها Deploy Key محدودشده را ترجیح بده.
- در حال حاضر دریافت خصوصی از طریق **SSH GitHub** پشتیبانی می‌شود. HTTPS عمومی از GitHub، GitLab، Bitbucket و Codeberg همچنان در فرم استقرار موجود است.

## ساخت Deploy Key از صفحهٔ اپلیکیشن

1. در «اپلیکیشن‌ها» کارت برنامه را باز کن و بخش «انتشار و نسخه‌ها» را انتخاب کن.
2. «استقرار منبع» را باز و «Git خصوصی · Deploy Key» را انتخاب کن.
3. آدرس SSH مخزن را وارد کن؛ نمونه: `git@github.com:acme/storefront.git`.
4. «ساخت Deploy Key» را بزن. ARG یک کلید Ed25519 می‌سازد و کلید خصوصی را فقط روی VPS ذخیره می‌کند.
5. «کپی» را بزن یا متن کلید عمومی را انتخاب کن. از لینک تنظیمات کنار فرم وارد صفحهٔ Deploy Keys همان مخزن GitHub شو.
6. در GitHub روی **Add deploy key** بزن، عنوانی وارد کن، کلید عمومی را بچسبان و گزینهٔ **Allow write access** را خاموش نگه دار.
7. برگرد به ARG، چک‌باکس تأیید ثبت کلید را علامت بزن، Branch یا tag را تعیین کن و Job استقرار را اجرا کن.

کلید عمومی را می‌توان چند بار دید و کپی کرد؛ کلید خصوصی هیچ‌گاه در API یا رابط کاربری نمایش داده نمی‌شود. اگر کلید در GitHub ثبت نشده باشد، اتصال SSH رد می‌شود و Job خطای دسترسی مخزن می‌دهد.

## مدیریت سراسری کلیدها

از نوار کناری «کلیدهای SSH» را باز کن. این صفحه برای VPS فضای‌کار انتخاب‌شده کلیدها را فهرست می‌کند و نام، اثر انگشت، مخزن محدودشده، زمان ایجاد و آخرین استفاده را نشان می‌دهد.

- **ساخت کلید:** Deploy Key برای یک مخزن مشخص بساز یا یک کلید شخصی برای افزودن به تنظیمات حساب انتخاب کن.
- **نمایش/کپی:** فقط کلید عمومی قابل بازیابی است.
- **تغییر نام:** عنوان مدیریتی ARG عوض می‌شود و کلید Git تغییر نمی‌کند.
- **حذف:** فایل خصوصی و کلید عمومی محلی پاک می‌شوند. برای لغو دسترسی از GitHub، کلید عمومی را از تنظیمات مخزن یا حساب GitHub نیز حذف کن.
- **دریافت مجدد Host Key:** ARG کلیدهای میزبان GitHub را از `api.github.com/meta` با HTTPS معتبر دریافت، با `ssh-keygen` بررسی و برای SSH سخت‌گیرانه ذخیره می‌کند.

حذف کلیدی که در Job فعال استفاده می‌شود تا پایان یا لغو Job متوقف می‌شود. تغییر نام یا حذف، Deploy Key ثبت‌شده در GitHub را تغییر نمی‌دهد.

## امنیت و مرزها

- کلید خصوصی Ed25519 در `/var/lib/arg/ssh-keys/<id>` با مجوز `0600` نگهداری می‌شود؛ پوشه `0700` است.
- Git با Batch Mode و Strict Host Key Checking اجرا می‌شود. کلید میزبان از HTTPS رسمی GitHub دریافت می‌شود و فایل `known_hosts` با کاربر و دسترسی محدود نگهداری می‌شود.
- URLهای Git دارای token یا رمز پشتیبانی نمی‌شوند. فرمان آزاد، shell string یا SSH config شخصی برای Deploy اجرا نمی‌شود.
- این رابط کلید را به GitHub اضافه نمی‌کند؛ برای این کار باید دسترسی GitHub OAuth یا token مدیریت مخزن در ARG ذخیره شود که در این جریان درخواست نمی‌شود.
- اگر کلید حذف شد، برای بازیابی دسترسی یک کلید تازه بساز، کلید عمومی تازه را در GitHub ثبت کن و دوباره Deploy را اجرا کن.

## API

- `GET /api/ssh-keys` — فهرست اطلاعات عمومی کلیدها، بدون محتوای خصوصی.
- `POST /api/ssh-keys` — ساخت کلید با `name`, `purpose` و برای Deploy Key فیلد `repository`؛ در صورت نیاز `application_id` نیز محدودیت اپ ایجاد می‌کند.
- `PUT /api/ssh-keys/{id}` — تغییر نام مدیریتی.
- `DELETE /api/ssh-keys/{id}` — حذف کلید محلی؛ Job فعال مانع حذف می‌شود.
- `GET|POST /api/ssh-keys/trusted-hosts/github` — خواندن وضعیت یا دریافت و اعتبارسنجی مجدد Host Keyهای GitHub.

همهٔ عملیات نوشتنی به مدیر، Origin معتبر و Audit نیاز دارند. نسخهٔ خصوصی کلید هیچ‌وقت در پاسخ API نیست.

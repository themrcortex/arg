## وضعیت و نصب

صفحه MySQL/MariaDB ابتدا نصب‌بودن server و سرویس را بررسی می‌کند. اگر نصب نیست، عملیات نصب از مخزن پکیج سیستم و با تأیید مدیر شروع می‌شود. نام سرویس می‌تواند `mysql` یا `mariadb` باشد.

## گشودن دسترسی مدیریتی

پیش از اجرای قابلیت‌های دیتابیس، ARG یک بار رمز فعلی حساب پنل را برای بازتأیید می‌خواهد. دسترسی مدیریتی به‌صورت کوتاه‌عمر و سمت سرور نگهداری می‌شود؛ رمز پنل در مرورگر ذخیره نمی‌شود. صفحهٔ MySQL را فقط در نشست مدیر مورد اعتماد باز کن.

ARG برای اتصال local به MySQL از credential موقت/پیکربندی محافظت‌شدهٔ helper استفاده می‌کند. رمز DB در پاسخ API یا لاگ نمایش داده نمی‌شود. Root یا admin دیتابیس ممکن است دسترسی وسیع داشته باشد؛ فرمان را با دقت اجرا کن.

## Databases و Users

کاتالوگ اطلاعات دیتابیس‌ها و کاربران را پس از احراز دسترسی می‌خواند. ساخت کاربر جدید باید به دیتابیس مشخص و حداقل Grant مورد نیاز محدود شود. رمز کاربر هنگام ساخت/set نمایش داده می‌شود تا مدیر امن آن را به صاحب سرویس تحویل دهد؛ ARG رمز قبلی MySQL را از hash قابل بازیابی نمی‌کند.

**Reset password** یک رمز جدید تنظیم می‌کند، رمز قبلی را بازیابی نمی‌کند. بعد از تغییر، برنامه‌هایی که credential قبلی دارند باید به‌روزرسانی و اتصالشان restart شود.

## سازگاری نسخه

نسخه‌های مختلف MySQL و MariaDB ستون‌های یکسانی در `mysql.user` ندارند؛ ARG ابتدا وضعیت قفل را هم می‌خواند؛ اگر نسخهٔ سرور ستون `account_locked` را نداشته باشد، خودکار با ستون‌های مشترک `user`, `host`, `plugin` دوباره تلاش می‌کند.

## اجرای SQL

Query editor برای عملیات SQL با زمان و خروجی محدود است. از SQL دلخواه در دیتابیس production ریسک دارد؛ `DROP`, `TRUNCATE`, `DELETE`، تغییر schema و تغییر privilege را تنها پس از backup و review اجرا کن. Transaction در همهٔ DDL یا همهٔ storage engineها رفتار rollback تضمین‌شده ندارد.

Query result ممکن است truncate شود یا با محدودیت row/time اجرا شود؛ پیام موفقیت به معنی صحت منطق برنامه نیست. Export دادهٔ حساس را در مسیر امن نگه‌دار.

## عیب‌یابی

- `unknown option '--defaults-extra-file'`: گزینه باید با `=` مستقیم به مسیر فایل داده شود، مانند `--defaults-extra-file=/path/file.cnf`; نسخهٔ جدید manager این شکل را می‌سازد.
- اگر فایل اعتبار داخلی ARG گم یا خراب باشد، ARG مجوزهای حساب رزروشدهٔ `arg_manager@localhost` را با root محلی بررسی می‌کند. بررسی خروجی `SHOW GRANTS` هم قالب تک‌کوتیشن MariaDB و هم backtick در MySQL را می‌پذیرد؛ خط بی‌اثر `GRANT USAGE` نیز مجاز است. فقط وقتی مجوز کامل سراسری ARG وجود داشته باشد و مجوز مؤثر دیگری به حساب داده نشده باشد، رمز تصادفی تازه می‌سازد، فایل root-only را آزمایش می‌کند و سپس جایگزین می‌کند. مجوزهای متفاوت یا اضافه را خودکار تغییر نمی‌دهد.
- دسترسی denied: سرویس، socket، method احراز هویت محلی و مجوز root را بررسی کن.
- رمز جدید کار نمی‌کند: user@host دقیق، plugin احراز هویت، secret برنامه و pool connection را بررسی کن.
- نصب شکست خورد: `apt-get update`, فضای `/var`, repository سیستم و log سرویس را بررسی کن.

## ورود و بخش‌های مدیریت

اولین بار که **مدیریت MySQL** باز می‌شود، صفحهٔ تأیید یک‌باره رمز پنل را برای نشست فعلی می‌خواهد. این رمز، رمز MySQL نیست. پس از تأیید، queryهای مدیریتی در همان نشست فعال می‌شوند و با خروج از حساب دسترسی منقضی می‌شود. اگر رمز را اشتباه زدی، خطا را بخوان و دوباره تلاش کن؛ از قرار دادن رمز DB در این فیلد خودداری کن.

وقتی وضعیت می‌خوانی، **MySQL/MariaDB نصب هست؟**، سرویس فعال، نسخه، provider و دسترسی helper را از هم جدا کن. نصب از مخازن APT سیستم است؛ انتخاب MySQL Server یا MariaDB Server، سرویس را نصب و فعال می‌کند و ممکن است حجم دیسک/سرویس را تغییر دهد. اگر دیتابیس موجود است، نصب دوباره را برای تعمیر بی‌هدف اجرا نکن.

- **دیتابیس‌ها:** ساخت/فهرست/حذف کاتالوگ. پیش از Drop نام و وابستگی برنامه را بررسی کن؛ حذف schema داده‌ها را نابود می‌کند.
- **کاربران:** نام و Host کاربر را بخوان. Host مانند `localhost` و `%` دامنهٔ اتصال متفاوتی دارد. برای کاربر جدید رمز قوی بساز، scope دیتابیس و حداقل privilege لازم را تعیین کن.
- **تغییر/فراموشی رمز:** reset رمز کاربر با دسترسی مدیر دیتابیس انجام می‌شود؛ رمز قبلی کاربر لازم نیست، اما رمز پنل برای unlock یک‌بار لازم است. پس از reset، secret جدید را به برنامه/`.env` امن وارد و pool را restart کن.
- **SQL Console:** queryهای SELECT را اول اجرا و نتیجه/تعداد ردیف را بررسی کن. DDL/DML مثل `DROP`, `TRUNCATE`, `UPDATE` ممکن است داده را دائماً تغییر دهند. Transaction فقط برای engine/tableهایی rollback می‌شود که پشتیبانی کنند؛ اجرای چند query تضمین atomic بودن نیست.
- **خروجی خطا:** خطاهای schema بین MySQL و نسخه‌های MariaDB تفاوت دارند. برای نمونه ستون `account_locked` در همهٔ نسخه‌ها موجود نیست؛ ARG در نسخهٔ سازگار fallback می‌کند. اگر query دستی آن را خطا داد، ابتدا `SELECT VERSION()` و `SHOW COLUMNS FROM mysql.user` را بخوان.

### نمونه: database و user کم‌دسترسی

1. نام دیتابیس lowercase مانند `shop_prod` بساز.
2. کاربر جدا مانند `shop_app` با Host محدود به `localhost` بساز؛ رمز یکتا تولید کن.
3. فقط مجوزهای موردنیاز روی `shop_prod.*` بده، نه `*.*` و `GRANT OPTION`.
4. مقادیر را در secret manager یا فایل config با دسترسی محدود ذخیره کن.
5. اتصال برنامه را تست کن و دسترسی admin داخلی ARG را برای اپلیکیشن استفاده نکن.

دکمهٔ Refresh وضعیت را دوباره می‌خواند. اگر MariaDB نصب است و فرم با query مخصوص MySQL شکست می‌خورد، نسخه/قابلیت را بررسی کن و خروجی خطای کامل را ذخیره کن؛ دستورات system table را بدون شناخت نسخه تغییر نده.

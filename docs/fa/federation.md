# اتصال پنل‌های ARG و مدیریت فضای‌کار راه‌دور

این صفحه رفتار نسخهٔ فعلی Federation را توضیح می‌دهد: هر VPS یک نصب مستقل ARG دارد و دو نصب با یک کد یک‌بارمصرف به هم اعتماد می‌کنند. پنلی که Node را اضافه می‌کند نقش Controller دارد؛ نصب مقصد همچنان مالک منابع و مرجع نهایی مجوزهاست. کد اتصال جایگزین نصب ARG روی مقصد نیست.

## پیش از اتصال

روی هر دو VPS نسخهٔ ARG را به‌روز نگه دار و برای پنل مقصد HTTPS معتبر آماده کن. در بخش **Nodeها** مقصد، نام عمومی سرور را تنظیم کن؛ این نام برای پنل‌های جفت‌شده ارسال می‌شود، درحالی‌که «برچسب محلی» فقط روی Controller دیده می‌شود. hostname سیستم تغییر نمی‌کند. سپس نقش مقصد را بررسی کن: `member` و `both` اجازهٔ ساخت کد ورودی دارند؛ `controller-capable` و `both` اجازهٔ افزودن Node خروجی دارند.

## نقش‌ها و اثرشان

| نقش | اتصال خروجی به Node | پذیرش Controller ورودی |
| --- | --- | --- |
| `standalone` | خیر | خیر |
| `member` | خیر | بله |
| `controller-capable` | بله | خیر |
| `both` | بله | بله |

این تنظیم، نصب مستقل ARG را خاموش نمی‌کند. تغییر نقش با تأیید مدیر انجام می‌شود. اگر اتصال‌های موجود با نقش جدید سازگار نباشند، ARG تعداد Nodeها یا Controllerهای وابسته را گزارش می‌کند و از حذف ناخواسته جلوگیری می‌کند. ابتدا از بخش Nodeها اتصال‌های مربوط را جدا کن، سپس نقش را تغییر بده.

## Pairing مرحله‌به‌مرحله

۱. روی مقصد به **Nodeها ← اجازهٔ مدیریت این سرور** برو و سطح دسترسی را انتخاب کن. «فقط‌خواندنی» وضعیت و مشاهده را می‌دهد؛ «کامل» عملیات مجاز سرویس، تغییرات فضای کار و ترمینال را هم اضافه می‌کند. حتی در حالت کامل، مقصد درخواست‌ها را مستقل اعتبارسنجی می‌کند.
۲. کد اتصال بساز. کد پس از ۵ دقیقه یا اولین استفاده منقضی می‌شود و فقط یک بار پذیرفته می‌شود؛ آن را در پیام عمومی یا Screenshot قرار نده.
۳. در Controller به **Nodeها ← اتصال این پنل به پنل دیگر** برو، یک برچسب محلی، URL پایهٔ HTTPS مقصد و کد را وارد کن.
۴. مقصد عمومی را به‌طور پیش‌فرض انتخاب کن. اگر مقصد با IP خصوصی یا DNS داخلی در شبکهٔ خصوصی مورداعتماد خودت است، گزینهٔ شبکهٔ خصوصی را روشن کن. loopback، link-local و endpointهای metadata در هر دو حالت مسدودند.
۵. بعد از Pairing، کارت Node را بررسی کن. وضعیت اتصال، سازگاری، scopeهای اعطاشده و زمان اعتبار نشست باید روشن باشند. انتخاب Node در نوار بالا فقط مقصد رابط را عوض می‌کند؛ مجوز عملیات همچنان از سمت مقصد می‌آید.

## Scope و رفتار نسخهٔ قدیمی

Controller token در فایل خصوصی سرور ذخیره می‌شود و به مرورگر یا localStorage فرستاده نمی‌شود. Scopeها شامل خواندن وضعیت، مشاهدهٔ سرویس‌ها، مدیریت سرویس، خواندن/نوشتن فضای کار، ترمینال و Root Terminal هستند. نشست مقصد برای هر درخواست scope لازم را بررسی می‌کند. درخواست‌های تغییردهنده در مقصد با نام Controller ثبت می‌شوند.

اگر یکی از پنل‌ها قابلیت مذاکره‌شدهٔ proxy را نداشته باشد، وضعیت `legacy-read-only` یا `incompatible` نمایش داده می‌شود. ARG برای سازگاری، مجوز اضافه‌تر نمی‌دهد؛ عملیات پشتیبانی‌نشده باید با پیام به‌روزرسانی و جفت‌سازی دوباره پاسخ داده شود. «همهٔ سرورها» نمای خواندنی تجمیعی است و مقصد عملیات نوشتن باید صریح انتخاب شود.

## اعتبارنامه، نشست و عیب‌یابی

کلید Controller تاریخ انقضا دارد. دکمهٔ چرخش کلید یک کلید تصادفی را ابتدا در فایل pending با دسترسی محدود ذخیره می‌کند، سپس آن را از کانال HTTPS به مقصد می‌فرستد و بعد از پاسخ موفق جایگزین می‌کند. اگر ارتباط قطع شود، فایل pending برای retry همان عملیات باقی می‌ماند. آن را دستی کپی یا حذف نکن؛ اگر عملیات چند بار شکست خورد، وضعیت شبکه و گواهی مقصد را بررسی و از Pairing مجدد استفاده کن.

نشست فضای کار ۱۲ ساعت اعتبار دارد و Controller پیش از انقضا آن را از مقصد تمدید می‌کند. وضعیت‌های اتصال عبارت‌اند از `healthy`، `degraded`، `offline`، `untrusted` و `incompatible`. خطاها و آخرین زمان بررسی روی کارت Node نمایش داده می‌شوند. `offline` را به معنی قطع سرویس ARG محلی فرض نکن؛ فقط دسترسی امن به Node راه‌دور برقرار نشده است.

برای لغو دسترسی، Node را از Controller حذف کن یا در مقصد دسترسی Controller را لغو کن. مقصد توکن را باطل و نشست‌های Proxy آن Controller را حذف می‌کند. حذف یک Node به معنی پاک‌کردن فایل‌ها یا برنامه‌های روی VPS مقصد نیست.

## محدودهٔ فعلی

مذاکرهٔ نسخه و scope، proxy فضای کار و ترمینال موجود است؛ با این حال تست کامل شبکه‌ای روی دو VPS واقعی باید پیش از استفادهٔ عملیاتی انجام شود. اگر تغییر نام عمومی یا بررسی وضعیت در بخشی از Nodeها شکست بخورد، ARG تعداد موارد همگام‌نشده را اعلام می‌کند و درخواست را به سرور دیگری منتقل نمی‌کند.

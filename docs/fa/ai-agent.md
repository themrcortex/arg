# اتصال عامل هوش مصنوعی به ARG

ARG یک endpoint سازگار با MCP در مسیر `/api/agent/mcp` ارائه می‌کند. اتصال با Bearer Token اختصاصی انجام می‌شود و فقط روی HTTPS در دسترس است.

## راه‌اندازی امن

1. با حساب مدیر وارد «مدیریت سرور و ARG» شو و کارت «اتصال عامل هوش مصنوعی (MCP)» را باز کن.
2. برای هر عامل یک توکن جدا بساز. دسترسی‌های لازم را دستی انتخاب کن؛ شروع فقط‌خواندنی توصیه می‌شود.
3. توکن را در Secret Manager کلاینت MCP ذخیره کن. توکن خام فقط یک‌بار نمایش داده می‌شود.
4. endpoint را به کلاینت MCP اضافه کن و توکن را از متغیر محرمانهٔ همان کلاینت بخوان.
5. پس از استفاده یا افشای احتمالی، توکن را از ARG لغو کن.

نمونهٔ پیکربندی مفهومی:

```json
{
  "mcpServers": {
    "arg": {
      "url": "https://arg.example.com/api/agent/mcp",
      "headers": { "Authorization": "Bearer ${ARG_AGENT_TOKEN}" }
    }
  }
}
```

## ابزارها و منابع

با توجه به scope توکن، عامل می‌تواند فهرست خلاصهٔ اپلیکیشن‌ها، خلاصهٔ Jobهای استقرار، وضعیت غیرمحرمانهٔ پنل، مستندات فارسی/انگلیسی و snapshot فایل‌های Rust و React/TypeScript همین نسخه را بخواند. منبع `arg://repository` به مخزن عمومی [themrcortex/arg](https://github.com/themrcortex/arg) اشاره می‌کند. منابع از فایل‌های بسته‌شده همراه binary خوانده می‌شوند؛ endpoint پنل URL دلخواه دریافت یا واکشی نمی‌کند.

در صورت صدور scope `deployments:propose`، عامل می‌تواند برای اپلیکیشنی که منبع پیش‌فرض ذخیره‌شده دارد پیشنهاد استقرار ثبت کند. منبع، Health Check، تعداد release و دستورهای پیش از استقرار همان لحظه snapshot می‌شوند؛ تغییر تنظیمات بعدی، پیشنهاد را عوض نمی‌کند. پیشنهاد به‌تنهایی عملیاتی اجرا نمی‌کند. مدیر باید نام اپ، دلیل، منبع snapshot‌شده و پیامد اجرای کد را در پنل بررسی و تأیید کند. تأیید، Job را از مسیر عادی استقرار ARG با همان اعتبارسنجی‌ها و صف اجرا می‌سازد.

scope اختیاری `terminal:root:propose` ابزار shell مستقیم نمی‌دهد؛ فقط اجازهٔ پیشنهاد یک فرمان یک‌خطی می‌دهد. هر فرمان باید جداگانه در پنل بررسی شود، مدیر باید رمز فعلی را دوباره وارد و عبارت `RUN AS ROOT` را تأیید کند. فرمان حداکثر ۲۰ ثانیه اجرا می‌شود و helper ممتاز پس از حداکثر ۳۰ ثانیه فرایند را متوقف می‌کند. نشست تعاملی یا دسترسی root دائمی به عامل داده نمی‌شود.

برای جلوگیری از نگهداری فرمان مدیریتی روی دیسک، متن پیشنهاد فقط در حافظهٔ پنل می‌ماند؛ پیشنهاد پس از ۵ دقیقه یا راه‌اندازی دوبارهٔ ARG باطل می‌شود. خروجی فرمان نیز در حافظهٔ موقت، حداکثر ۱۶ KiB و تا ۵ دقیقه نگه‌داری می‌شود و عامل فقط یک‌بار می‌تواند آن را بخواند. خروجی برای همان عامل قابل مشاهده است و ممکن است دادهٔ حساس داشته باشد؛ فرمانی را تأیید کن که به خروجی آن عامل اعتماد داری.

مجوزهای توکن را می‌توان از پنل ویرایش کرد. حذف مجوز root، درخواست‌های معلق را باطل می‌کند. scopeهای shell، خواندن/افشای Secret، پراکسی عمومی API، حذف منابع، تغییر شبکه یا کنترل مستقیم سرویس در MCP وجود ندارند.

## کنترل‌های امنیتی

* کلید تصادفی ۲۵۶ بیتی تولید و فقط hash آن ذخیره می‌شود.
* کلید حداکثر ۳۰ روز اعتبار دارد؛ مقدار پیشنهادی UI هفت روز است.
* هر کلید حداکثر ۳۰ درخواست در دقیقه دارد و scopeها مستقل‌اند.
* حداکثر ۱۰ کلید فعال برای هر مدیر و ۲۰ پیشنهاد معلق برای هر کلید پذیرفته می‌شود.
* توکن با تنزل نقش یا غیرفعال‌شدن مالک لغو می‌شود.
* پیشنهادها پس از ۳۰ دقیقه منقضی می‌شوند؛ اجرا فقط با تأیید نشست مدیر و کنترل Origin انجام می‌شود.
* پیشنهاد فرمان Root پس از ۵ دقیقه منقضی می‌شود؛ برای هر اجرا بررسی متن، تأیید مجدد رمز و عبارت تأیید لازم است.
* فرمان و خروجی root در SQLite یا Audit Log نوشته نمی‌شوند؛ خروجی حداکثر ۱۶ KiB و فقط یک‌بار در حافظهٔ موقت ارائه می‌شود.
* پاسخ‌ها `no-store` هستند و رویدادهای ساخت، لغو، پیشنهاد و بررسی در Audit ثبت می‌شوند.
* محدودکردن دسترسی شبکه به پنل و محافظت از کلیدهای کلاینت MCP همچنان مسئولیت مدیر سرور است.

## عیب‌یابی

* `401`: توکن اشتباه، منقضی یا لغوشده است؛ کلید جدید بساز.
* `403`: scope لازم انتخاب نشده یا درخواست روی HTTPS نیست.
* `429`: سقف ۳۰ درخواست در دقیقه رد شده؛ polling را کمتر کن.
* scope `repository:read` برای خواندن فایل‌های source لازم است و از scope مستندات جداست.
* ابزار پیشنهاد استقرار، اپلیکیشن بدون منبع پیش‌فرض ذخیره‌شده را نمی‌پذیرد.
* مجوزهای توکن فعال از پنل قابل تغییر هستند؛ scope root فقط درخواست فرمان می‌دهد و اجرای آن همیشه نیازمند رمز و تأیید دوبارهٔ مدیر است.

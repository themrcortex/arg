## ARG در یک نگاه

ARG یک کنترل‌سنتر خودمیزبان برای مدیریت VPS لینوکسی است. پنل در مرورگر اجرا می‌شود، اما عملیات سیستم را Backend نوشته‌شده با Rust انجام می‌دهد. رابط وب با React و TypeScript ساخته شده و صفحه‌ها برای کارهای عملیاتی طراحی شده‌اند: خواندن وضعیت، تغییر پیکربندی، اجرای عملیات محدودشده و دیدن نتیجه.

ARG جایگزین پنل ارائه‌دهندهٔ VPS، سامانهٔ مانیتورینگ سازمانی یا سامانهٔ پشتیبان‌گیری مستقل نیست. ARG اتصال امن بین پنل‌ها را از طریق Nodeهای جفت‌شده پشتیبانی می‌کند و می‌تواند برای Nodeهای سازگار فضای کار را به سرور راه‌دور تغییر دهد. این قابلیت به معنی اجرای عمومی و یکپارچهٔ Rollout روی کل ناوگان نیست؛ پیش‌نمایش Rollout و شبکهٔ خصوصی پیش‌نویس، روی VPS قانون شبکه اعمال نمی‌کنند. دادهٔ واقعی فقط وقتی نمایش داده می‌شود که سیستم‌عامل یا سرویس مربوط آن را گزارش کند. قابلیت‌های برنامه‌ریزی‌شده در این راهنما به‌عنوان قابلیت موجود معرفی نمی‌شوند.

## قابلیت‌های موجود

- داشبورد و ثبت پس‌زمینهٔ تاریخچهٔ CPU، حافظه، دیسک و نرخ ترافیک شبکه در SQLite.
- فهرست رابط‌های شبکه، پورت‌های شنونده و ابزار تست اتصال TCP محلی.
- مدیریت UFW، قانون‌های TCP/UDP و پورت‌های محافظت‌شدهٔ SSH و ARG.
- مدیریت سایت‌های Nginx، کانفیگ، وضعیت، دامنه، SSL، حالت تعمیرات، اکشن‌های اختصاصی و محدودیت منابع سرویس‌های مستقل.
- مدیریت Docker/Compose و منابع موجود Engine؛ عملکردهای خطرناک با عملیات تأییدی انجام می‌شوند.
- فایل‌منیجر سیستم با بارگذاری/دریافت، عملیات فایل، ZIP امن و تحلیل مصرف دیسک.
- اتصال S3-compatible، مرور Object، انتقال بین دیسک و Bucket و بررسی مصرف Bucket.
- مدیریت پایه MySQL/MariaDB، کاربران دیتابیس، اجرای SQL کنترل‌شده و بازیابی رمز.
- APT، سرویس‌های systemd، ترمینال، کاربران پنل، نشست‌ها، گزارش Audit و ابزار پشتیبان/بازیابی ARG.
- مدیریت اپلیکیشن با Jobهای پایدار، releaseهای جدا، گزارش مرحله‌ها، Runnerهای موجود و بازگشت کد. نوع Runtime و عملیات قابل انجام به پلتفرم پشتیبانی‌شده بستگی دارد.
- اتصال Nodeهای ARG، نمایش سلامت و انتخاب فضای کار سرور؛ به‌روزرسانی راه‌دور فقط برای Node سازگار و مجاز در دسترس است.

## از کجا شروع کنم؟

- **نصب امن پنل:** [نصب و شروع سریع](./install.md) را بخوان و پس از ورود، [ملاحظات امنیتی](./security.md) را مرور کن.
- **ساخت و انتشار سایت:** از [فهرست اپلیکیشن‌ها](./application-registry.md) شروع کن؛ سپس [Job استقرار](./deployment-jobs.md) و راهنمای [Node.js](./node-runner.md) یا [Laravel](./laravel-runner.md) را بر اساس Runtime بخوان.
- **مدیریت وب‌سایت موجود:** راهنمای [Nginx و SSL](./nginx.md) را دنبال کن؛ قبل از تغییر کانفیگ یا صدور گواهی، پیش‌نیازها و rollback همان بخش را ببین.
- **وصل‌کردن VPS دوم:** [جفت‌سازی و مدیریت Nodeها](./federation.md) نقش کنترل‌کننده، کد یک‌بارمصرف، scope دسترسی و محدودیت‌های سازگاری را توضیح می‌دهد.
- **پیداکردن فضای مصرف‌شده:** از [تحلیل فایل‌ها](./files.md) برای زیرشاخه‌ها و [سیستم و دیسک](./system-storage.md) برای Mount و ظرفیت واقعی استفاده کن.
- **انتقال فایل به Object Storage:** ابتدا [اتصال و مدیریت S3](./s3.md) را بخوان؛ مصرف پیمایش‌شده، quota قرارداد و صورتحساب Provider سه مفهوم متفاوت‌اند.
- **به‌روزرسانی یا بازیابی پنل:** [Updates](./updates.md) و [Backup و نگهداری](./maintenance.md) را قبل از عملیات تغییر نسخه مرور کن.

جزئیات محدودیت هر بخش در صفحهٔ همان قابلیت نوشته شده است. برای مثال، فضای S3 فقط زمانی ظرفیت کل دارد که Provider آن را گزارش کند؛ در غیر این صورت سقف «نامشخص» است و مصرف از پیمایش Objectها محاسبه می‌شود.

## اصول طراحی

1. **دادهٔ معتبر:** مقدار نامعلوم به‌صورت «نامشخص» گزارش می‌شود و با صفر یا دادهٔ نمونه جایگزین نمی‌شود.
2. **مرز دسترسی:** عملیات عادی در Backend Rust اعتبارسنجی می‌شود. کارهای روتی فقط از طریق Helper محدود و فهرست‌شده انجام می‌شوند.
3. **تغییر قابل‌ردیابی:** عملیات مدیریتی در Audit ثبت می‌شوند؛ گذرواژه، کلید و محتوای محرمانه نباید در لاگ قرار گیرند.
4. **بازگشت‌پذیری:** به‌روزرسانی پنل باینری قبلی و snapshot دیتابیس را برای rollback نگه می‌دارد. این جایگزین بکاپ مستقل نیست.
5. **خطر آشکار:** تغییرات شبکه، فایروال، SSL، فایل و سرویس باید هدف و اثرشان را روشن کنند.

## دامنهٔ پشتیبانی

نصب‌کننده برای Debian و Ubuntu مبتنی بر systemd طراحی شده است. ابزارها و نام بسته‌ها با نسخه و توزیع تفاوت دارند؛ پیش از اجرای عملیات تولیدی، VPS آزمایشی و snapshot سمت ارائه‌دهنده را ترجیح بده. ARG دسترسی SSH خارج از band را جایگزین نمی‌کند.

## نسخه و شاخه

`main` شاخهٔ پایدار و `development` شاخهٔ پیش‌انتشار است. نسخهٔ نمایش‌داده‌شدهٔ سایت مستندات از نسخهٔ Cargo شاخه‌ای می‌آید که GitHub Pages را ساخته است؛ releaseهای پایدار را در [`CHANGELOG.md`](https://github.com/themrcortex/arg/blob/main/CHANGELOG.md) ببین. بین شاخه‌ها برابری قابلیت یا API را فرض نکن و برای Node راه‌دور، سازگاری نسخه و capabilityهای مذاکره‌شده را بررسی کن.

## پیش‌نیازها

- VPS لینوکسی Debian یا Ubuntu با `systemd` و دسترسی `root` یا `sudo`.
- دسترسی شبکه برای دریافت وابستگی‌ها، GitHub و دریافت بسته‌های توزیع.
- فضای آزاد کافی برای toolchain Rust و کامپایل نسخهٔ release؛ اندازهٔ موقت build به معماری، وابستگی‌ها و Cache بستگی دارد.
- پورت پنل از فایروال سیستم‌عامل و Firewall پنل ارائه‌دهنده قابل دسترسی باشد. برای TLS از روش HTTP-01، پورت TCP 80 نیز باید موقتاً برای ACME قابل دسترسی باشد.

ARG رسماً فقط Debian/Ubuntu + systemd را هدف می‌گیرد. توزیع‌های دیگر ممکن است کار کنند، اما تضمین و آزمون انتشار برایشان تعریف نشده است.

## نصب سریع بدون Clone

اسکریپت رسمی را دریافت و با دسترسی root اجرا کن:

```bash
curl --proto '=https' --tlsv1.2 -fsSL \
  https://raw.githubusercontent.com/themrcortex/arg/main/install.sh -o arg.sh
sudo bash arg.sh install
```

برای نمایش منوی کامل نصب و مدیریت، `install` را حذف کن:

```bash
sudo bash arg.sh
```

نصب‌کننده وابستگی‌های سیستم را نصب می‌کند، Rust stable را آماده می‌کند، سورس شاخهٔ انتخابی را دریافت می‌کند، Frontend تعبیه‌شده و Backend را می‌سازد، حساب سرویس محدود `arg` را می‌سازد و سرویس‌های `arg.service` و `arg-privileged.service` را تنظیم می‌کند.

> اسکریپت نصب با دسترسی root اجرا می‌شود. پیش از اجرا، نشانی راستی‌آزمایی‌شدهٔ مخزن و محتوای نصب‌کننده را بررسی کن؛ روی سروری که به آن اعتماد نداری، اسکریپت remote را مستقیم اجرا نکن.

## تنظیمات نصب

نصب‌کننده پورت و IP عمومی را تشخیص می‌دهد و خلاصهٔ آدرس را در پایان نشان می‌دهد. آدرس عمومی VPS ممکن است به‌علت محدودیت egress یا پاسخ سرویس‌های تشخیص IP پیدا نشود؛ این امر به‌تنهایی به معنی خرابی شبکهٔ پنل نیست.

### SSL اختیاری است

در مرحلهٔ HTTPS می‌توانی `skip` وارد کنی. نصب ARG به دریافت گواهی وابسته نیست. اگر Let's Encrypt یا منبع جایگزین ZeroSSL شکست بخورد، نصب با HTTP ادامه پیدا می‌کند و می‌توان HTTPS را بعداً راه‌اندازی کرد. مرورگر هنگام HTTP رمز و نشست را رمزنگاری نمی‌کند؛ تا وقتی TLS را فعال نکرده‌ای، پنل را فقط با SSH tunnel یا شبکهٔ مورد اعتماد باز کن.

ZeroSSL برای گواهی ACME دامنه به EAB KID و HMAC نیاز دارد و گواهی IP صادر نمی‌کند. استفاده از ZeroSSL اختیاری است؛ در صورت نداشتن EAB یا شکست دسترسی شبکه، درخواست را رد کن و بعداً گواهی سازگار را دستی در پنل تنظیم کن.

## ورود امن با SSH tunnel

اگر TLS آماده نیست، Tunnel را از رایانهٔ خود باز نگه دار:

```bash
ssh -N -L 8282:127.0.0.1:8282 <SSH_USER>@<SERVER_IP>
```

سپس در همان رایانه به `http://127.0.0.1:8282` برو. پورت سمت راست Tunnel باید با پورت پنل روی VPS برابر باشد. در صورت تغییر پورت، هر دو عدد را به‌روز کن.

## ساخت مدیر نخست

- با HTTPS عمومی: کد یک‌بارمصرف راه‌اندازی را از خروجی نصب‌کننده یا منوی `arg` بگیر و در صفحهٔ ساخت مدیر وارد کن.
- با Tunnel: صفحهٔ محلی را از طریق SSH باز کن و کد یک‌بارمصرف سرور را وارد کن.

کد راه‌اندازی فقط برای ایجاد اولین مدیر است؛ پس از ساخت مدیر دیگر قابل استفاده نیست. آن را در پیام‌رسان یا لاگ عمومی منتشر نکن.

## بررسی سرویس پس از نصب

```bash
sudo arg status
sudo systemctl is-enabled arg
sudo journalctl -u arg -n 100 --no-pager
```

سرویس باید فعال باشد و صفحهٔ ورود از Loopback پاسخ دهد. برای بازکردن دسترسی از اینترنت، پورت واقعی پنل را در Firewall سیستم و پنل ارائه‌دهنده باز کن؛ برای HTTP عمومی، فعال‌کردن HTTPS را در اولویت قرار بده.

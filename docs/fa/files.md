## مرور فایل‌ها

فایل‌منیجر مسیر جاری سرور را نشان می‌دهد و امکان رفتن به پوشه، جست‌وجوی نام، ساخت فایل/پوشه، ویرایش متن، دریافت و بارگذاری فایل را دارد. مسیرها سمت سرور هستند؛ نام نمایشی سایت معادل document root نیست. برای بازکردن فایل‌های یک سایت، root را از کانفیگ Nginx بررسی کن.

## عملیات

- **Copy/Paste:** کپی فایل یا پوشه به مقصد انتخابی؛ نام و مسیر مقصد را کنترل کن تا دادهٔ مهمی بازنویسی نشود.
- **Cut/Move:** تغییر محل فایل/پوشه. برای انتقال بین فایل‌سیستم‌های جدا ممکن است کپی و سپس حذف منبع رخ دهد و زمان‌بر باشد.
- **Rename:** تغییر نام داخل همان پوشه.
- **Delete:** حذف فایل یا درخت پوشه؛ این کار به Trash منتقل نمی‌شود و بازگشت‌پذیر نیست.
- **Upload/Download:** انتقال از مرورگر به سرور و بالعکس؛ محدودیت اندازه و timeout با سرور و مرورگر وابسته است.
- **Edit:** ویرایش متن؛ فایل Binary را ویرایش نکن. قبل از دستکاری کانفیگ زنده، نسخهٔ پشتیبان بگیر.
- **ZIP:** ساخت آرشیو از فایل یا پوشهٔ منتخب و دانلود آن.
- **Unzip:** استخراج آرشیو در پوشهٔ جدید؛ path traversal، symlink، overwrite و اندازهٔ بیش از حد رد می‌شوند.

نسخهٔ فعلی محدودیت اندازه و تعداد entry برای آرشیو دارد؛ خطای limit به معنی خراب‌بودن ZIP نیست. فایل بزرگ را می‌توان با SSH/rsync منتقل کرد.

## امنیت و دسترسی

فایل‌منیجر عملیات پرقدرت دارد. فایل‌های کلید، `/etc`, دیتابیس و فایل‌های سرویس را فقط با دلیل روشن تغییر بده. Symlink ممکن است به مسیری خارج اشاره کند؛ نسخهٔ جاری بعضی عملیات تخریبی/ZIP آن را رد می‌کند، اما همیشه مقصد واقعی را بررسی کن. permission نامناسب می‌تواند سرویس را از کار بیندازد یا secret را عمومی کند.

## انتقال پوشهٔ بزرگ به S3

برای انتقال درخت دایرکتوری به Bucket از صفحهٔ S3 و انتقال VPS به Bucket استفاده کن. فرایند شامل انتخاب مسیر، مقصد و بازبینی تعداد/حجم است. انتقال کپی داده ایجاد می‌کند؛ تا وقتی checksum/فهرست فایل مقصد را بررسی نکرده‌ای، منبع را حذف نکن. انتقال کامل یک سرویس یا Container به S3 جایگزین migration سازگار اپلیکیشن نیست.

## راهنمای قدم‌به‌قدم مرورگر فایل

صفحه **مدیریت فایل‌ها** به‌عنوان کاربر احراز هویت‌شدهٔ ARG فایل‌سیستم VPS را مرور می‌کند. نوار مسیر LTR است. برای بازکردن مسیر، مسیر absolute مانند `/var/www/example` را وارد و **رفتن** را بزن؛ **پوشهٔ بالاتر** یک سطح به عقب می‌رود. دسترسی به مسیر به allowlist و مجوزهای helper محدود است؛ دیدن نام مسیر در UI تضمین نمی‌کند کاربر مجاز است آن را بخواند یا تغییر دهد.

فهرست شامل نام، نوع، اندازه، permission، آخرین تغییر و عملیات است. برای رفتن داخل directory روی نام آن کلیک کن؛ برای فایل متنی، ویرایشگر را باز کن؛ symlink را با مقصدش اشتباه نگیر. فایل باینری را در ویرایشگر متن ذخیره نکن. قبل از تغییر فایل config، محتوای فعلی را کپی/backup کن. دکمهٔ تازه‌سازی فقط فهرست را دوباره می‌خواند.

### عملیات فایل و پوشه

- **ساخت پوشه/فایل:** مسیر والد را بررسی کن، نام نسبی ساده انتخاب کن، سپس ساخت را تأیید کن.
- **آپلود:** فایل از مرورگر به سرور می‌رسد؛ سقف اندازه و timeout را رعایت کن. برای فایل بزرگ ترجیح بده انتقال مستقیم VPS↔S3 یا SCP/rsync را استفاده کنی.
- **دانلود:** فایل انتخاب‌شده از سرور دریافت می‌شود. برای symlink اول مقصد را بررسی کن.
- **Rename/Move:** نام مقصد را کامل بررسی کن؛ انتقال بین mountها ممکن است از نظر سیستم‌عامل Copy/Delete باشد و اتمیک نباشد.
- **Copy/Cut/Paste:** انتخاب Copy/Cut در clipboard برنامه ثبت می‌شود؛ Paste مقصد جاری است. Cut را فقط پس از کنترل مسیر مقصد اجرا کن.
- **ZIP:** یک یا چند فایل/پوشه را به آرشیو تبدیل و سپس دانلود کن. آرشیو بزرگی که داخل پوشهٔ خودش ساخته شود ممکن است در اسکن بعدی دوباره داخل خودش وارد شود؛ مقصدی جدا مثل `/tmp/arg-exports` انتخاب کن.
- **Unzip:** قبل از استخراج، آرشیو و مقصد را بررسی کن. نام‌های داخل ZIP باید به مقصد محدود بمانند؛ فایل هم‌نام را بازنویسی ناخواسته نکن. حجم فشرده و فضای آزاد مقصد را پیش از Extract بسنج.
- **Delete:** عملیات برگشت‌پذیر فرض نشود. مسیر، تعداد و نوع موارد را بخوان؛ پوشهٔ اصلی سرویس، symlink حساس یا mountpoint را حذف نکن.
- **دسترسی‌ها:** فقط permission لازم را بده؛ `777` راه‌حل عمومی نیست. کاربر/گروه سرویس وب را بررسی کن تا فایل‌ها هم امن باشند هم قابل‌خواندن.

### تحلیل مصرف دیسک

بخش تحلیل، مسیر شروع `/` یا مسیر دیگر را می‌پذیرد و زیرشاخه‌ها را باز می‌کند. هر ردیف اندازهٔ recursive همان مسیر را گزارش می‌کند؛ بنابراین والد شامل اندازهٔ فرزندان است. جمع‌زدن ردیف والد و فرزند دوباره‌شماری ایجاد می‌کند. برای پیدا کردن علت پرشدن دیسک، از بزرگ‌ترین شاخه شروع کن، آن را باز کن، تا به فایل یا cache بزرگ برسی. `du` می‌تواند زمان و I/O مصرف کند؛ اسکن `/` را در زمان بار بالا تکرار نکن و مسیر `/proc`, `/sys`, `/dev` یا Mount ابری را با فایل‌سیستم محلی اشتباه نگیر.

**نمونه:** اگر `/var/lib/containerd` بزرگ است، به `/var/lib/containerd/io.containerd.snapshotter.v1.overlayfs` پایین برو و قبل از پاک‌کردن، صفحه Docker و `docker system df -v` را مقایسه کن. snapshotهای فعال یا cache build را دستی از containerd پاک نکن؛ پاک‌سازی Docker فقط بعد از بررسی image/container/volume انجام شود. برای لاگ‌ها `journalctl --disk-usage` و log rotation را بررسی کن، نه این‌که فایل در حال نوشتن را مستقیم truncate کنی.

### ZIP امن و بازگردانی

برای انتقال پوشه، پوشهٔ منبع را انتخاب کن و مقصد را خارج از source انتخاب کن؛ اگر عملیات خطا داد، فایل مبدأ را نگه‌دار. پس از ساخت ZIP، فهرست/اندازهٔ آرشیو را ببین و آن را به سیستم خود دانلود کن. برای بازیابی، ZIP را upload کن، به مسیر مقصد برو و Extract را اجرا کن؛ محتوا را پس از استخراج با مسیر و تعداد مورد انتظار تطبیق بده. ZIP جایگزین backup دیتابیس یا snapshot سرویس نیست.

### Permissionها و ویرایش فایل

ستون Mode به‌شکل octal نمایش داده می‌شود؛ مثلاً `0644` یعنی owner خواندن/نوشتن و بقیه خواندن، `0755` برای directory امکان traverse می‌دهد. تغییر mode، owner یا group را با نوع سرویس هماهنگ کن؛ PHP-FPM/Nginx لازم نیست همهٔ فایل‌ها را بنویسد. برای uploadهای قابل نوشتن، فقط پوشهٔ لازم مثل `storage` یا `uploads` writable باشد. قبل از تغییر `nginx.conf`, `.env` یا فایل unit، نسخهٔ قبلی را دانلود/کپی و diff را بررسی کن.

Editor برای متن محدود و مناسب فایل config کوچک است؛ برای SQLite، image، archive، فایل خیلی بزرگ یا newline-sensitive binary استفاده نکن. اگر فایل بزرگ است، صفحه ممکن است محتوا را محدود کند. پس از Save، metadata و syntax برنامه را بررسی کن. برای Nginx `nginx -t`; برای JSON با parser معتبر؛ برای env فقط format و permissions.

### الگوی پوشه‌بندی انتقال

اگر می‌خواهی `/var/www/site/public/uploads` را به S3 ببری، ابتدا از مسیر فایل‌ها scan بگیر و symlinkها را شناسایی کن. محتوا را به prefix یکتا مثل `site-assets-2026/` منتقل و تعداد/حجم فایل را مقایسه کن. اپلیکیشن را روی endpoint/object adapter تنظیم کن و چند فایل read/write آزمایش کن. تنها پس از صحت cache/CDN/permission منبع محلی را archive کن. فایل‌های session، cache زودگذر و دیتابیس زنده را صرفاً با ZIP به S3 منتقل نکن.

## قابلیت‌های موجود در نسخهٔ فعلی

ARG می‌تواند اتصال S3-compatible بسازد، اتصال را آزمایش کند، Bucket را وصل کند، Objectها را صفحه‌بندی‌شده فهرست کند، Object را بارگذاری/دانلود/حذف کند، انتقال پوشه و فایل بین VPS و Bucket انجام دهد، Mount با Rclone بسازد و مصرف Objectها را اسکن کند. Providerهای مستقل شامل AWS، Cloudflare R2، آروان، پارس‌پک، Backblaze B2، DigitalOcean Spaces، Wasabi، MinIO و endpoint عمومی S3-compatible هستند.

هر Provider تمام APIهای AWS را تضمین نمی‌کند. تست اتصال، دسترسی‌های قابل مشاهده و عملیات Bucket جداگانه‌اند؛ کلیدی که اجازهٔ فهرست‌کردن همهٔ Bucketها ندارد ممکن است برای Bucket شناخته‌شده کار کند.

## اتصال Provider

۱. «اتصال جدید» را بزن و Provider را انتخاب کن. ۲. نام نمایشی داخلی، Endpoint، Region امضای درخواست و Access Key را وارد کن. ۳. Secret Key را فقط در زمان ساخت/چرخش ثبت کن؛ بعد از ذخیره قابل بازیابی از API نیست. ۴. Endpoint باید HTTPS باشد؛ endpoint خصوصی فقط با گزینهٔ صریح و بررسی مقصد شبکه مجاز می‌شود. ۵. تست اتصال را اجرا و نتیجهٔ read/list/write را جداگانه مرور کن. ۶. Bucket موجود را انتخاب یا نام آن را وارد و بررسی کن.

### Preset آروان

Endpoint براساس منطقهٔ انتخابی دریافت می‌شود؛ برای نمونه Endpoint سیمین `s3.ir-thr-at1.arvanstorage.ir` و شهریار `s3.ir-tbz-sh1.arvanstorage.ir` است. Host endpoint با Signing Region یکی نیست. Region امضا را از مستندات/پنل همان سرویس بگیر و حدس نزن.

### Preset پارس‌پک

Endpoint اختصاصی را از پنل فضای ابری پارس‌پک وارد کن. مقدار ثابت عمومی یا Region حدسی استفاده نکن. راهنمای رسمی را از [مستندات پارس‌پک](https://docs.parspack.com/cloud-storage/) بررسی کن.

## مرور Bucket و Object

ساختار پوشه‌ای S3 در اصل Prefix و نام کلیدهاست، نه فایل‌سیستم POSIX. لیست به‌صورت صفحه‌ای دریافت می‌شود تا Bucket بزرگ یک‌باره در حافظه بار نشود. هر Object اندازه و زمان/ETag را در صورت ارائهٔ API نشان می‌دهد. Upload در API فعلی حداکثر 512 MiB و Download حداکثر 2 GiB است.

حذف Object یک عملیات مخرب است. حذف اتصال از ARG فقط Association محلی را جدا می‌کند؛ Bucket و دادهٔ Provider را پاک نمی‌کند. عملیات حذف واقعی Bucket یا APIهایی مانند lifecycle/versioning در نسخهٔ جاری برای همهٔ Providerها مدیریت عمومی ندارند.

## انتقال بین فایل‌سیستم VPS و S3

- **Local → Bucket:** مسیر فایل یا پوشه را انتخاب کن، Bucket و Prefix مقصد را تعیین و فهرست/حجم را بازبینی کن. پوشه با حفظ ساختار نسبی انتقال می‌یابد.
- **Bucket → Local:** Prefix/Object را انتخاب و مسیر مقصد را تعیین کن. مسیر باید در مجوزهای فایل‌منیجر باشد و نوشتن روی فایل موجود فقط طبق کنترل‌های UI/API انجام می‌شود.
- انتقال منبع را به‌صورت خودکار حذف نمی‌کند؛ پس از پایان، تعداد فایل‌ها و دادهٔ مقصد را بررسی کن.
- انتقال بین S3 و VPS یک Copy است، نه جابه‌جایی اتمیک. قطع شبکه، quota، timeout یا revoke شدن key می‌تواند بخشی از مجموعه را منتقل کند. در خطا منبع را نگه‌دار و خروجی عملیات را بررسی کن.
- این ابزار تضمین‌کنندهٔ migration سازگار از سایت یا دیتابیس زنده نیست. برای سرویس پویا ابتدا maintenance/quiesce، backup، سازگاری فایل/DB، آزمون مقصد و برنامهٔ rollback لازم است.

## Mount با Rclone

هر Bucket می‌تواند در `/mnt/arg-s3/connection-<id>-bucket-<id>` به‌صورت FUSE mount شود. نصب Rclone باید جداگانه از APT انجام شود. Mount پیش‌فرض **read-only** است؛ فقط با درک محدودیت S3 آن را read-write کن. امکان auto-mount هنگام boot وجود دارد.

کلید و تنظیمات Rclone در فایل محافظت‌شده قرار می‌گیرند و در argv قابل مشاهده نیستند. systemd unit اختصاصی برای Mount ساخته می‌شود. Cache نوشتن در مسیر `/var/cache/arg-s3` با سقف 1 GiB و عمر 24 ساعت است. توقف Mount از پنل امکان‌پذیر است.

> Mount شدن S3 ظرفیت `/` یا دیسک فیزیکی را زیاد نمی‌کند. ظرفیت Remote را `statvfs` محلی نمی‌تواند معتبر گزارش کند. Cache Rclone روی دیسک VPS فضا می‌گیرد و باید در محاسبهٔ مصرف دیسک در نظر گرفته شود.

## مصرف و سهمیه

مصرف Bucket از جمع اندازهٔ Objectهای صفحه‌بندی‌شده محاسبه می‌شود. نخستین اسکن یا درخواست دستی، کار شبکه‌ای ایجاد می‌کند؛ نتیجه تا 24 ساعت cache می‌شود تا فهرست کامل دائماً تکرار نشود. شکست اسکن به مقدار صفر تبدیل نمی‌شود. وضعیت fresh/stale/scanning/failed را همراه زمان آخرین اندازه‌گیری بخوان.

Provider معمولاً سقف Bucket را از API عمومی S3 گزارش نمی‌کند. اگر قرارداد سقف دارد، آن را در فیلد quota وارد کن؛ منبع آن «دستی/قرارداد» است و با مصرف واقعی یکی نیست. نسخهٔ جاری پرداخت/صورتحساب Provider و یادآور تمدید کامل را مدیریت نمی‌کند.

## مواردی که هنوز تضمین/پیاده نشده‌اند

Rclone Mount و انتقال پوشه موجودند؛ اما سازگاری POSIX کامل نیست. Scheduled sync/mirror عمومی، حذف خودکار منبع، deployment MinIO، Object Lock، replication، billing API، versioning/lifecycle عمومی و migration اتمیک سایت/Container به S3 در نسخهٔ جاری وجود ندارند. هیچ‌یک را جایگزین backup مستقل ندان.

## اتصال S3 در پنل، فیلد به فیلد

برای شروع به **فضای ابری S3** برو و «اتصال جدید» را انتخاب کن. مرحلهٔ اول فقط سرویس را مشخص می‌کند؛ اتصال در مرحلهٔ بعد با ذخیره ساخته می‌شود. نام اتصال دلخواه و داخلی ARG است، مثلاً `آرشیو بکاپ`. این نام را با نام Bucket اشتباه نگیر. فیلد اختیاری Bucket موجود اجازه می‌دهد از همان ابتدا یک Bucket را به اتصال اضافه کنی؛ اگر خالی باشد، اتصال حساب Provider ذخیره می‌شود و Bucket را بعداً انتخاب می‌کنی.

| فیلد | چه چیزی وارد شود | از کجا پیدا می‌شود / نمونه |
|---|---|---|
| Provider | سرویس دقیق میزبان داده | AWS، R2، ArvanCloud، ParsPack، Backblaze B2، DigitalOcean Spaces، Wasabi، MinIO یا Generic |
| نام نمایشی اتصال | برچسب قابل فهم برای خودت | `Backup VPS production`؛ روی نام واقعی Objectها اثری ندارد |
| Bucket موجود | نام Bucket ساخته‌شده در Provider | مثلاً `backup-prod-01`؛ حروف کوچک، عدد و دش امن‌تر است |
| Endpoint URL | HTTPS origin مربوط به منطقه/حساب | بدون نام Bucket، path، query string یا credential؛ R2 نمونه: `https://<ACCOUNT_ID>.r2.cloudflarestorage.com` |
| Region / Signing Region | منطقه‌ای که امضای درخواست باید با آن سازگار باشد | مقدار را از صفحهٔ تنظیم اتصال همان Provider بردار؛ از روی hostname حدس نزن |
| Addressing Style | نحوهٔ قرار گرفتن نام Bucket در درخواست | ابتدا `Auto`؛ اگر سرویس custom با TLS و نام Bucket نقطه‌دار مشکل دارد، `Path-style` را امتحان کن |
| Access Key ID | شناسهٔ کلید برنامه‌ای | از صفحهٔ Access Keys/API Keys/Application Keys سرویس؛ معمولاً قابل مشاهده است |
| Secret Access Key | راز جفت کلید | موقع ساخت کلید همان لحظه کپی کن؛ ARG آن را دوباره نمایش نمی‌دهد |
| Session Token | Token کوتاه‌مدت در صورت استفاده از credentials موقت | فقط اگر Provider برای آن جفت کلید Session Token صادر کرده باشد؛ تاریخ انقضا را رعایت کن |
| Endpoint خصوصی | اجازهٔ دسترسی به MinIO یا مقصد داخلی‌ای که خودت کنترل می‌کنی | روشن‌کردن آن تأیید جدا می‌خواهد؛ metadata و مقصدهای حساس همچنان مسدودند |

فیلدهای LTR را بدون فاصلهٔ ابتدا/انتها وارد کن. Endpoint باید Origin کامل با `https://` باشد؛ `s3.region.example.net/bucket` را به‌عنوان Endpoint نده، Bucket در فیلد جداست. برای AWS Endpoint را خالی بگذار تا SDK endpoint استاندارد را انتخاب کند. برای دیگر Providerها که فرم Endpoint می‌خواهد، فقط آدرس سرویس را بگذار. Region هم نام منطقهٔ درخواست است، نه کشور سرور ARG.

### ساخت کلید کم‌دسترسی

اگر فقط فایل‌ها را می‌خوانی، کلید Read-only بساز. برای انتقال فایل از VPS به Bucket، دست‌کم Put/Write و برای پاک‌کردن Objectها مجوز Delete لازم است. فهرست Bucketهای حساب ممکن است مجوز جداگانه بخواهد؛ اگر کلید فقط به Bucket مشخص محدود است، نام Bucket را دستی وارد کن و آزمون همان Bucket را اجرا کن. نداشتن مجوز ListBuckets لزوماً به معنی خرابی credential نیست. دسترسی ساخت/حذف Bucket را به کلید روزمره نده مگر واقعاً قرار است ARG Bucket بسازد.

در ARG Secret بعد از ثبت بازخوانی نمی‌شود. برای چرخش کلید، تنظیمات اتصال را باز کن، Access Key ID و Secret جدید را وارد و ذخیره کن؛ در ویرایش، خالی‌گذاشتن فیلدها کلید قبلی را حفظ می‌کند. ابتدا کلید جدید را در پنل Provider فعال کن، در ARG تست بگیر، بعد کلید قبلی را revoke کن. این ترتیب احتمال قطعی را کم می‌کند.

## راهنمای دریافت مقادیر برای هر Provider پشتیبانی‌شده

مسیر دقیق منوهای شرکت‌ها ممکن است با نسخهٔ پنل یا زبان حساب تغییر کند. عنوان‌های زیر نام بخش‌هایی هستند که باید جست‌وجو کنی؛ صفحهٔ مستند رسمی هر Provider را هم از لینک کنار نام باز کن. ARG نمی‌تواند برایت حساب تجاری بخرد یا کلید را صادر کند.

### Amazon S3

1. در AWS Console به **S3 → Buckets** برو و Bucket را در Region مورد نظر بساز یا از Bucket موجود استفاده کن. نام Region را از Bucket properties/عنوان Region بردار، مانند `eu-central-1`؛ این همان Region در فرم ARG است.
2. به **IAM → Users** برو و یک کاربر/role مخصوص ARG بساز. Policy را به Bucket و prefix لازم محدود کن؛ برای مرور و دانلود `ListBucket` و `GetObject`، برای آپلود `PutObject` و فقط در صورت نیاز حذف `DeleteObject` بده.
3. در **Security credentials → Access keys** برای کاربری که مجاز است کلید ایجاد کن. Access Key ID و Secret Access Key هنگام ساخت ظاهر می‌شوند؛ Secret را همان لحظه در password manager نگه دار.
4. در ARG Provider را **Amazon S3** انتخاب کن، Endpoint را خالی بگذار، Region را دقیقاً مانند AWS Console وارد کن، سپس جفت کلید را وارد و اتصال را تست کن.
5. اگر AWS role/credential موقت بدون کلید ثابت استفاده می‌کنی، فقط در صورتی فرم و backend فعلی از نوع credential آن پشتیبانی کند از آن استفاده کن؛ هر سه مقدار Access/Secret/Session Token باید از یک نشست باشند.

**نمونه:** Bucket=`arg-nightly-eu`, Region=`eu-central-1`, Endpoint خالی، Addressing=`Auto`. اگر `AccessDenied` دیدی، Policy همان Bucket/prefix و عملیات لازم را بررسی کن؛ Region را تصادفی عوض نکن.

### Cloudflare R2

1. در Cloudflare Dashboard وارد **Storage & databases → R2 → Overview** شو. اگر هنوز R2 فعال نیست، ابتدا سرویس را فعال کن و Bucket را از **Create bucket** بساز.
2. از Account Details، **Account ID** را بردار. endpoint اصلی به شکل `https://<ACCOUNT_ID>.r2.cloudflarestorage.com` است؛ Account ID را جایگزین کن. برای Bucketهای jurisdiction مشخص، endpoint همان jurisdiction لازم است؛ endpoint عمومی را کورکورانه به‌کار نبر.
3. در **R2 → Manage API Tokens → Create Account API token** یا User API token، دسترسی **Object Read & Write** را فقط به Bucket موردنظر scope کن. اگر فقط مشاهده لازم است Read را انتخاب کن. ساختن credential ممکن است نیاز به فعال/خرید R2 داشته باشد.
4. در صفحهٔ نتیجه، **Access Key ID** و **Secret Access Key** را فوراً کپی کن؛ Secret دوباره قابل مشاهده نیست. endpoint را از همان صفحه یا R2 Overview تأیید کن.
5. ARG: Provider=`Cloudflare R2`، Endpoint بالا، Region=`auto`، Bucket دقیق، و دو کلید را وارد کن. تست اتصال را بزن.

`auto` منطقهٔ امضای موردنیاز سازگاری S3 در R2 است و به معنی حدس Region از IP نیست. APIهای مدیریتی R2 همهٔ قابلیت‌های AWS را ندارند؛ اگر عملیاتی غیرفعال یا unsupported است، فقط با عوض‌کردن Region آن را رفع نمی‌کنی.

### ابر آروان / ArvanCloud

1. در پنل آروان **فضای ابری** را باز کن و سرویس/منطقهٔ محل Bucket را پیدا کن. Bucket (در نام‌گذاری مستندات آروان «صندوقچه») را در همان منطقه بساز؛ Bucket در ARG ساخته نمی‌شود چون این Provider preset آن قابلیت ساخت Bucket را اعلام نمی‌کند.
2. طبق مستند SDK رسمی آروان، Access Key و Secret Key را در داشبورد فضای ابری پنل آروان پیدا/ایجاد کن. این کلیدهای **S3** با Machine User/API Key مدیریتی آروان یکی نیستند؛ توکن API مدیریت زیرساخت را در فیلد S3 نگذار.
3. Endpoint رسمی منطقه را با صفحهٔ Bucket تطبیق بده. presetهای ARG عبارت‌اند از: ایران مرکز ۱: `https://s3.ir-central1.arvanstorage.ir`؛ سیمین: `https://s3.ir-thr-at1.arvanstorage.ir`؛ شهریار: `https://s3.ir-tbz-sh1.arvanstorage.ir`. اگر پنل منطقه یا endpoint متفاوتی نشان می‌دهد، گزینهٔ سفارشی را بزن و مقدار پنل خودت را مبنا بگیر.
4. فیلد **Signing Region** منطقهٔ امضای S3 است و با Host/Endpoint یکی نیست. در صورت ارائهٔ Region در مشخصات اتصال/SDK همان سرویس آن را وارد کن. برای Endpoint ایران مرکز ۱، preset مقدار `ir-central1` را پیشنهاد می‌دهد. برای سیمین/شهریار اگر مقدار مستقل Signing Region در پنل/راهنما روشن نیست، از پشتیبانی/راهنمای رسمی بگیر؛ `ir-thr-at1` یا `ir-tbz-sh1` را صرفاً از روی hostname حدس نزن.
5. نام Bucket را از فهرست فضای ابری بردار، نه نام نمایشی ARG. کلید S3 را با دسترسی فقط به همان Bucket بساز اگر پنل اجازه می‌دهد.

**نمونهٔ قابل‌استفاده:** Provider=`ابر آروان`، منطقهٔ ایران مرکز ۱، Endpoint=`https://s3.ir-central1.arvanstorage.ir`، Region=`ir-central1`, Bucket=`arg-backups`, Access/Secret از داشبورد فضای ابری. اگر اتصال در `SignatureDoesNotMatch` شکست خورد، Region امضا و ساعت سیستم سرور را بررسی کن؛ کلید مدیریتی Machine User را جایگزین کلید S3 نکن.

### پارس‌پک / ParsPack Cloud Storage

1. وارد پنل پارس‌پک شو و سرویس **فضای ابری** را باز کن. Bucket را از همان پنل بساز یا یک Bucket موجود انتخاب کن؛ خرید سرویس یا ساختن Bucket از ARG انجام نمی‌شود.
2. راهنمای رسمی پارس‌پک بخش‌های **پیشخوان و مدیریت دسترسی** و **نحوه اتصال به فضای ابری** را معرفی می‌کند. در پنل، مشخصات اتصال/مدیریت دسترسی را باز کن و S3 Endpoint/REST Endpoint، Access Key و Secret Key را بردار. Endpoint اختصاصی سرویس/حساب است؛ مقدار عمومی ساختگی استفاده نکن.
3. اگر Secret فقط یک بار نمایش داده شد، همان لحظه آن را امن ذخیره کن. اگر کلید محدود به یک Bucket ساختی، مجوز ListBuckets ممکن است وجود نداشته باشد؛ Bucket name را از نمای همان سرویس کپی و در فرم ARG دستی وارد کن.
4. Provider=`پارس‌پک` را انتخاب کن. Endpoint را دقیقاً از پنل paste کن؛ scheme `https://` و Host را با مستند حساب تطبیق بده. Region را فقط وقتی سرویس در مشخصات اتصال ارائه کرده پر کن؛ ARG برای ParsPack Region ثابت حدس نمی‌زند. Access Key/Secret و Bucket را ثبت و تست کن.

اگر آدرس از پنل به‌صورت hostname بدون scheme کپی شد، فقط در صورتی آن را `https://` کن که مستند همان endpoint TLS را تأیید کند. خطاهای 403 معمولاً به scope/مجوز یا نام Bucket مربوط‌اند؛ خطای TLS/DNS را با تغییر کلید حل نکن.

### Backblaze B2 (S3-Compatible)

1. در Backblaze Web Console مطمئن شو B2 Cloud Storage فعال است. از **B2 Cloud Storage → Buckets** Bucket بساز یا Bucket مقصد را باز کن؛ در جزئیات آن مقدار Endpoint/Region را یادداشت کن.
2. در **B2 Cloud Storage → Application Keys → Add a New Application Key** یک کلید استاندارد بساز؛ از master key حساب برای S3-compatible API استفاده نکن. Bucket موردنظر را محدود کن و Read/Write یا Read Only را بر اساس کار انتخاب کن. اگر ARG باید فهرست کل Bucketهای حساب را بگیرد، گزینهٔ `List all bucket names` مجوز اضافه می‌خواهد؛ امن‌تر است Bucket را دستی تعیین کنی.
3. Key ID به فیلد Access Key ID و Application Key به Secret Access Key نگاشت می‌شوند. Application Key فقط هنگام ساخت نمایش داده می‌شود.
4. Endpoint قالب `https://s3.<region>.backblazeb2.com` دارد؛ مثلاً اگر صفحهٔ Bucket `us-west-004` نشان داد، از `https://s3.us-west-004.backblazeb2.com` استفاده کن. Region را هم همان کد `us-west-004` بگذار، نه یک Region نامرتبط AWS.
5. در ARG `Backblaze B2` را انتخاب، Endpoint/Region/Bucket/کلید را وارد و تست کن. برای Delete Object ممکن است هم `writeFiles` و هم `deleteFiles` لازم باشد.

### DigitalOcean Spaces

1. در Control Panel **Spaces Object Storage → Buckets** را باز و Bucket موجود را انتخاب کن. صفحهٔ Overview، **origin endpoint** همان Bucket را نشان می‌دهد؛ قالب معمول `<region>.digitaloceanspaces.com` است، مثل `nyc3.digitaloceanspaces.com`. Region دقیق Bucket را از همان endpoint بگیر.
2. به **Spaces Object Storage → Access Keys → Create Access Key** برو. اگر گزینه دارد، دسترسی را فقط به Bucket و Read یا Read/Write لازم محدود کن. Access Key ID و Secret موقع ساخت نشان داده می‌شود؛ Secret را ذخیره کن چون بعداً قابل بازیابی نیست.
3. در ARG Endpoint را با `https://` و hostname منطقه وارد کن (مثلاً `https://nyc3.digitaloceanspaces.com`)، Region را `nyc3` بگذار، سپس Bucket و key pair را وارد کن.

نام Bucket را به Endpoint اضافه نکن؛ Bucket فیلد جداست. اگر Bucket نقطه در نام دارد و TLS/virtual-hosted style مشکل می‌دهد، `Path-style` را امتحان کن. ایجاد کلید محدودشده و scopeها تابع امکانات و محدودیت فعلی Spaces است.

### Wasabi

1. در Wasabi Console سرویس و Bucket را بررسی کن؛ منطقهٔ Bucket را از صفحهٔ خود Bucket بخوان.
2. از **Access Keys → Create Access Key** کلید را برای حساب اصلی یا Sub-user انتخاب و ایجاد کن. در صورت امکان یک Sub-user و دسترسی حداقلی بساز. Wasabi حداکثر دو کلید هم‌زمان برای هر user گزارش می‌کند؛ هنگام چرخش کلید این محدودیت را در نظر بگیر.
3. endpoint باید متناسب با Region باشد. برای نمونه US East 1: `https://s3.wasabisys.com` یا alias منطقه‌ای `https://s3.us-east-1.wasabisys.com`; برای مناطق دیگر جدول رسمی Service URLs را ببین و endpoint همان منطقه را انتخاب کن.
4. Region را دقیقاً مطابق console و endpoint وارد کن. Access Key ID/Secret Key را در ARG بگذار؛ نام Bucket را از فهرست Bucketهای همان منطقه بردار.

از endpoint عمومی US East برای Bucket منطقهٔ دیگری استفاده نکن. اگر تست TLS/DNS موفق ولی امضا رد شد، اول endpoint و Region جفت را تطبیق بده.

### MinIO

MinIO را روی VPS یا شبکهٔ مورد اعتماد خودت راه‌اندازی و Bucket و Service Account/Access Key را در MinIO Console یا `mc` بساز. از root/admin credentials اصلی MinIO استفاده نکن؛ کاربر اختصاصی برای Bucket و دسترسی لازم ایجاد کن. Endpoint همان آدرس HTTPS API سرور MinIO است، برای مثال `https://minio.example.net:9000` یا endpoint داخلی مثل `https://10.0.0.8:9000`.

برای endpoint خصوصی، گزینهٔ **Endpoint خصوصی / شبکهٔ داخلی** را در ARG روشن و تأیید کن؛ فقط IP/hostname تحت کنترل خودت را وارد کن. پورت Console معمولاً با API پورت متفاوت دارد: endpoint S3 باید API endpoint باشد، نه صفحهٔ Console. Region را مطابق config سرور MinIO وارد کن؛ اگر region اختصاصی تنظیم نشده، از مقدار مستند deployment استفاده کن و `us-east-1` را فقط وقتی پیکربندی MinIO/کلاینت چنین توافقی دارد بگذار. ابتدا Addressing=`Auto` را تست کن؛ در شبکه داخلی و DNS بدون wildcard، `Path-style` گاهی سازگارتر است.

### Generic S3-Compatible / Custom

این گزینه برای سرویس‌هایی است که در preset فهرست نشده‌اند یا endpoint سازگار اختصاصی دارند. از پنل سرویس‌دهنده این مقادیر را بردار: **S3 endpoint**, **signing region**, **Bucket**, **Access Key ID**, **Secret Access Key**, و در صورت استفاده **Session Token**. از همان‌جا بررسی کن که key اجازهٔ List/Get/Put/Delete کدام‌ها را دارد و آیا bucket-level listing فعال است. Endpoint را با HTTPS و بدون path وارد کن؛ Region را از مستند رسمی بگیر. اگر provider فقط از Path-style پشتیبانی می‌کند، Addressing Style را `Path-style` بگذار.

## تست اتصال را چطور بخوانم؟

دکمهٔ **بررسی اتصال** یک درخواست واقعی و چندمرحله‌ای انجام می‌دهد و Object نشانگر `arg-verify` را در Bucket انتخابی می‌نویسد/به‌روزرسانی می‌کند، دوباره می‌خواند و در Bucket باقی می‌گذارد. این فایل تست را دستی پاک نکن مگر مطمئن باشی دیگر به آن نیاز نداری؛ این تست جابه‌جایی کامل فایل‌ها یا سازگاری همهٔ APIها را تضمین نمی‌کند.

| نتیجه | معنی و اقدام |
|---|---|
| Endpoint/DNS/TLS fail | Host، scheme، DNS، ساعت TLS، خروجی پورت 443 و گواهی endpoint را کنترل کن |
| Credential/Signature fail | Access/Secret را از یک جفت کپی کن؛ whitespace، Region امضا، ساعت VPS و روش addressing را بررسی کن |
| Bucket listing denied | ممکن است key عمداً محدود باشد؛ Bucket را دستی وارد و تست همان Bucket را بزن |
| `arg-verify` write denied | مجوز PutObject یا prefix محدودشده را اصلاح کن؛ برای اتصال فقط‌خواندنی این تست نوشتن ممکن است مناسب نباشد |
| Write موفق، read fail | مجوز GetObject/HeadObject یا سازگاری API provider را بررسی کن |
| بررسی موفق | endpoint و کلید برای همین عملیات آزمون‌شده جواب داده‌اند؛ این نتیجه مجوز Delete، ساخت Bucket، ACL یا Lifecycle را ثابت نمی‌کند |

## چرخش credential بدون توقف

1. کلید جایگزین را در پنل Provider بساز و آن را هنوز revoke نکن.
2. در ARG اتصال را ویرایش کن. اگر فقط Secret را می‌چرخانی، شناسهٔ کلید جدید و Secret جدید را وارد کن؛ فیلدهای credential را خالی گذاشتن، کلید فعلی را نگه می‌دارد.
3. ذخیره کن و تست `arg-verify` را اجرا کن.
4. اگر موفق شد، mount/انتقال‌های مصرف‌کننده را کنترل کن و بعد کلید قدیمی را در Provider revoke کن.
5. اگر شکست خورد، کلید قدیمی را نگه‌دار، endpoint/permission/region را اصلاح و دوباره تست کن.

## محدودیت‌هایی که در انتخاب عملیات باید در نظر بگیری

- «افزودن اتصال» یا حذف اتصال در ARG، Bucket و Objects ارائه‌دهنده را نمی‌سازد یا پاک نمی‌کند. حذف واقعی Bucket عملیات متفاوت و destructive است و قابلیت عمومی آن برای همهٔ Providerها وجود ندارد.
- S3 فولدر POSIX ندارد؛ مسیرهای نمایشی prefix هستند. Rename فولدر/آبجکت معمولاً Copy+Delete است و در صورت قطع شبکه می‌تواند نیمه‌کاره بماند.
- اتصال Read-only برای مرور/دانلود است؛ انتقال VPS→Bucket به مجوز نوشتن نیاز دارد. Read-only را برای Mount اولیه پیشنهاد می‌کنیم.
- پشتیبانی از Bucket listing، CreateBucket، policy، versioning، ACL و lifecycle بین Providerها متفاوت است. unavailable بودن یک capability به معنی نامعتبر بودن کل اتصال نیست.
- اسکن حجم با صفحه‌بندی Objectها انجام می‌شود؛ برای Bucket بزرگ هزینهٔ درخواست و زمان می‌خواهد. نتیجهٔ ذخیره‌شده تا 24 ساعت cache می‌شود. `failed` را صفر نخوان.
- Mount ابری ظرفیت دیسک فیزیکی VPS را اضافه نمی‌کند. cache محلی Rclone خودش فضای دیسک VPS مصرف می‌کند.
- انتقال پوشه به شکل مجموعه‌ای از Objects انجام می‌شود؛ اگر وسط کار خطا رخ داد، نتیجهٔ هر عملیات را بررسی کن، فایل مبدأ را نگه‌دار و قبل از تکرار از وجود Object مقصد مطمئن شو.

## Capabilityهای واقعی preset در ARG

این جدول وضعیت preset فعلی کد ARG را می‌گوید؛ مجوز واقعی همچنان به key و سرویس‌دهنده وابسته است. گزینهٔ فعال در UI به معنی تضمین همهٔ قابلیت‌های S3 نیست.

| preset | Endpoint در فرم | Region لازم در preset | Create Bucket از ARG |
|---|---|---|---|
| Amazon S3 | اختیاری؛ endpoint AWS پیش‌فرض | بله | اعلام‌شده در preset؛ به Policy و Region وابسته |
| Cloudflare R2 | لازم؛ شامل Account ID | خیر؛ مقدار قراردادی `auto` | اعلام‌شده، اما API capabilityهای AWS را کامل ندارد |
| ArvanCloud | لازم؛ endpoint منطقه‌ای/سفارشی | بله؛ signing region را از سند بگیر | در preset فعلی خیر |
| ParsPack | لازم؛ endpoint حساب کاربر | مقدار حدسی ندارد | در preset فعلی خیر |
| Backblaze B2 | لازم؛ شامل Region حساب | بله | در preset فعلی خیر |
| DigitalOcean Spaces | لازم؛ regional endpoint | بله | اعلام‌شده، محدود به API/key |
| Wasabi | لازم؛ regional service URL | بله | اعلام‌شده، محدود به API/key |
| MinIO | لازم؛ S3 API host | اختیاری/طبق تنظیم سرور | اعلام‌شده، با دسترسی داخلی/سرویس |
| Generic | لازم؛ custom HTTPS origin | اختیاری؛ مستند Provider | در preset فعلی خیر |

اگر Create Bucket برای preset غیرمجاز است، آن را با افزودن یک اتصال جدید دور نزن؛ Bucket را از کنترل پنل ارائه‌دهنده بساز و بعد در ARG با نام موجود متصل کن. وضعیت UI/Backend ممکن است با نسخهٔ Provider تغییر کند؛ رفتار تست‌شدهٔ endpoint را مرجع بگیر.

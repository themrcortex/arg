## اطلاعات سیستم

صفحهٔ سیستم مشخصات میزبان، uptime، CPU، RAM، Swap و فایل‌سیستم‌ها را در یک محل جمع می‌کند. بخش دیسک‌ها mountهای محلی، مجازی و Remote را تفکیک می‌کند؛ یک mount تکراری نباید به‌عنوان ظرفیت مستقل دوباره جمع شود.

## معنی ظرفیت دیسک

- **Total:** بلوک‌های کل فایل‌سیستم.
- **Used:** بلوک‌های اشغال‌شده.
- **Available:** فضایی که برای کاربر عادی قابل استفاده است؛ ممکن است از Free کمتر باشد چون بخشی برای root رزرو شده.
- **Reserved/unavailable:** اختلاف Total با Used و Available در صورت قابل محاسبه بودن.
- **Mount point:** مسیری که فایل‌سیستم درخت دایرکتوری را به آن متصل می‌کند؛ برای مثال `/`, `/var`, `/mnt/data`.

`/proc`, `/sys`, `tmpfs`, `overlay`، cgroup و pseudo-filesystemها فضای فیزیکی مستقل نیستند و از مجموع دیسک‌های محلی کنار گذاشته می‌شوند. Mountهای FUSE/S3 در بخش Remote/Cloud هستند، نه ظرفیت واقعی دیسک محلی. Cache لوکال Rclone همچنان دیسک محلی را مصرف می‌کند.

## تحلیل فضای اشغال‌شده

ابزار تحلیل دیسک با پیمایش محدود، پوشه‌ها و فایل‌های بزرگ را رتبه‌بندی می‌کند. مقدار پوشه، مجموع زیرشاخه‌هاست؛ بنابراین نباید مقدار والد و فرزند را با هم جمع کرد. گزینهٔ پیمایش mountهای دیگر یا شکستن محدودیت اسکن می‌تواند زمان، I/O و بار CPU را زیاد کند. مسیرهای مجازی، دایرکتوری‌های پویا و فایل‌هایی که حین اسکن تغییر می‌کنند ممکن است اختلاف ایجاد کنند.

برای پیدا کردن مصرف واقعی در SSH می‌توان از این فرمان‌های فقط‌خواندنی استفاده کرد:

```bash
sudo df -hT
sudo du -xhd1 /var /opt /home 2>/dev/null | sort -h
sudo docker system df -v
```

`du -x` از رفتن به فایل‌سیستم mountشدهٔ دیگر جلوگیری می‌کند. پیش از حذف cache، Image، log یا release قدیمی، مطمئن شو سرویس فعالی به آن وابسته نیست.

## نمودار Read/Write

نرخ خواندن/نوشتن زمانی نمایش داده می‌شود که counterهای block device در سیستم موجود باشد. این نرخ ترافیک برنامه‌ها را نشان نمی‌دهد و به‌طور کلی نمی‌تواند I/O یک سایت یا Container را جدا کند. مقادیر میان reboot یا تغییر device قابل مقایسهٔ مستقیم نیستند؛ نمودار نرخ و نمودار capacity دو مفهوم متفاوت‌اند.

## ریسک پاک‌سازی

هرگز برای آزادکردن فضا دستی مسیرهای `/var/lib/docker`, `/var/lib/containerd`, دیتابیس، `/opt/arg` یا دایرکتوری سایت را با `rm -rf` پاک نکن. ابتدا مالک داده و اتصال آن به سرویس را پیدا کن؛ از Docker prune فقط پس از بازبینی موارد حذف‌شونده استفاده کن.

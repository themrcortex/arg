## Available in the current release

ARG can create S3-compatible connections, test them, associate Buckets, list Objects with pagination, upload/download/delete Objects, transfer files and directories between the VPS and a Bucket, create Rclone FUSE mounts, and scan Object usage. Provider choices include AWS, Cloudflare R2, ArvanCloud, ParsPack, Backblaze B2, DigitalOcean Spaces, Wasabi, MinIO, and generic S3-compatible endpoints.

No provider is guaranteed to support every AWS API. Connection checks, permissions, and bucket actions are reported separately; a key without account-wide bucket listing may still work with a known Bucket.

## Connect a provider

1. Select **New connection** and the provider. 2. Enter an internal display name, Endpoint, request-signing Region, and Access Key. 3. Enter the Secret Key only when creating or rotating credentials; it is not retrievable from the API after save. 4. Use HTTPS by default; private endpoints require explicit opt-in and destination checks. 5. Test the connection and review read/list/write permissions. 6. Select an existing Bucket or enter a known Bucket name and verify it.

### ArvanCloud preset

Endpoints depend on the selected region. For example, Simin uses `s3.ir-thr-at1.arvanstorage.ir` and Shahriar uses `s3.ir-tbz-sh1.arvanstorage.ir`. The endpoint hostname and signing Region are different concepts. Obtain the signing Region from the provider's docs/account; do not guess it from the host.

### ParsPack preset

Enter the dedicated Endpoint shown in the ParsPack cloud-storage account panel. Do not use a guessed universal Endpoint or Region. Consult [ParsPack's official storage documentation](https://docs.parspack.com/cloud-storage/).

## Browse buckets and objects

An S3 “folder” is a prefix in Object keys, not a POSIX directory. Listings are paginated to avoid loading a large bucket at once. Object size and modified time/ETag appear when the provider returns them. Current API limits are 512 MiB for upload and 2 GiB for download.

Deleting an Object is destructive. Removing a connection from ARG only detaches its local association; it does not delete the provider Bucket or data. Actual bucket deletion and universally available lifecycle/versioning APIs are not general features in the current release.

## Transfer between VPS and S3

- **Local → Bucket:** choose a file or directory, destination Bucket and prefix, then review the listing/size. Directory transfers preserve relative structure.
- **Bucket → Local:** choose a prefix/Object and destination path. The path must be permitted by the file manager; existing-file writes follow the UI/API safety checks.
- Transfers do not automatically delete the source. After completion, verify destination object count and content.
- VPS/S3 transfer is a copy, not an atomic move. Network loss, quota, timeout, or revoked credentials can leave a partial transfer. Keep the source and inspect operation results before retrying.
- This does not guarantee a consistent migration of a live site or database. For dynamic services, plan maintenance/quiescing, backup, application-level consistency, destination verification, and rollback first.

## Rclone mount

A Bucket can be mounted via FUSE at `/mnt/arg-s3/connection-<id>-bucket-<id>`. Install Rclone separately through APT. Mounts default to **read-only**; enable write access only after considering S3's POSIX limitations. Auto-mount at boot is available.

Credentials and Rclone configuration are stored in a protected file and are not exposed in process arguments. A dedicated systemd unit runs the mount. Write cache uses `/var/cache/arg-s3`, capped at 1 GiB with a 24-hour age. Mounts can be stopped from the panel.

> Mounting S3 does not increase `/` or physical disk capacity. Local `statvfs` cannot reliably report remote object-storage capacity. Rclone cache consumes VPS disk and must be included in local disk analysis.

## Usage and quota

Bucket usage is computed by summing paginated Object sizes. The first scan or a manual scan uses network/API resources; results are cached for up to 24 hours to avoid repeatedly listing the entire Bucket. A failed scan is not converted to zero. Check fresh/stale/scanning/failed state and the last measurement time.

Providers often do not expose a reliable Bucket quota through the generic S3 API. If you have a contractual quota, record it manually; its source is shown as manual/contract and it is not the measured usage. Provider billing and complete renewal reminders are not managed in this release.

## Not implemented or universally guaranteed

Rclone mounts and directory transfers are available, but they are not full POSIX filesystems. General scheduled sync/mirror, automatic source deletion, MinIO server deployment, Object Lock, replication, billing APIs, universal versioning/lifecycle management, and atomic website/container migration to S3 are not available in this release. Do not treat any of these as an independent backup system.

## Available in the current release

ARG can create S3-compatible connections, test them, associate Buckets, list Objects with pagination, upload/download/delete Objects, transfer files and directories between the VPS and a Bucket, create Rclone FUSE mounts, and scan Object usage. Provider choices include AWS, Cloudflare R2, ArvanCloud, ParsPack, Backblaze B2, DigitalOcean Spaces, Wasabi, MinIO, and generic S3-compatible endpoints.

No provider is guaranteed to support every AWS API. Connection checks, permissions, and bucket actions are reported separately; a key without account-wide bucket listing may still work with a known Bucket.

## Connect a provider

1. Select **New connection** and the provider. 2. Enter an internal display name, Endpoint, request-signing Region, and Access Key. 3. Enter the Secret Key only when creating or rotating credentials; it is not retrievable from the API after save. 4. Use HTTPS by default; private endpoints require explicit opt-in and destination checks. 5. Test the connection and review read/list/write permissions. 6. Select an existing Bucket or enter a known Bucket name and verify it.

### ArvanCloud preset

Endpoints depend on the selected region. For example, Simin uses `s3.ir-thr-at1.arvanstorage.ir` and Shahriar uses `s3.ir-tbz-sh1.arvanstorage.ir`. The endpoint hostname and signing Region are different concepts. Obtain the signing Region from the provider's docs/account; do not guess it from the host.

### ParsPack preset

Enter the dedicated Endpoint shown in the ParsPack cloud-storage account panel. Do not use a guessed universal Endpoint or Region. Consult [ParsPack's official storage documentation](https://docs.parspack.com/cloud-storage/).

## Browse buckets and objects

An S3 “folder” is a prefix in Object keys, not a POSIX directory. Listings are paginated to avoid loading a large bucket at once. Object size and modified time/ETag appear when the provider returns them. Current API limits are 512 MiB for upload and 2 GiB for download.

Deleting an Object is destructive. Removing a connection from ARG only detaches its local association; it does not delete the provider Bucket or data. Actual bucket deletion and universally available lifecycle/versioning APIs are not general features in the current release.

## Transfer between VPS and S3

- **Local → Bucket:** choose a file or directory, destination Bucket and prefix, then review the listing/size. Directory transfers preserve relative structure.
- **Bucket → Local:** choose a prefix/Object and destination path. The path must be permitted by the file manager; existing-file writes follow the UI/API safety checks.
- Transfers do not automatically delete the source. After completion, verify destination object count and content.
- VPS/S3 transfer is a copy, not an atomic move. Network loss, quota, timeout, or revoked credentials can leave a partial transfer. Keep the source and inspect operation results before retrying.
- This does not guarantee a consistent migration of a live site or database. For dynamic services, plan maintenance/quiescing, backup, application-level consistency, destination verification, and rollback first.

## Rclone mount

A Bucket can be mounted via FUSE at `/mnt/arg-s3/connection-<id>-bucket-<id>`. Install Rclone separately through APT. Mounts default to **read-only**; enable write access only after considering S3's POSIX limitations. Auto-mount at boot is available.

Credentials and Rclone configuration are stored in a protected file and are not exposed in process arguments. A dedicated systemd unit runs the mount. Write cache uses `/var/cache/arg-s3`, capped at 1 GiB with a 24-hour age. Mounts can be stopped from the panel.

> Mounting S3 does not increase `/` or physical disk capacity. Local `statvfs` cannot reliably report remote object-storage capacity. Rclone cache consumes VPS disk and must be included in local disk analysis.

## Usage and quota

Bucket usage is computed by summing paginated Object sizes. The first scan or a manual scan uses network/API resources; results are cached for up to 24 hours to avoid repeatedly listing the entire Bucket. A failed scan is not converted to zero. Check fresh/stale/scanning/failed state and the last measurement time.

Providers often do not expose a reliable Bucket quota through the generic S3 API. If you have a contractual quota, record it manually; its source is shown as manual/contract and it is not the measured usage. Provider billing and complete renewal reminders are not managed in this release.

## Not implemented or universally guaranteed

Rclone mounts and directory transfers are available, but they are not full POSIX filesystems. General scheduled sync/mirror, automatic source deletion, MinIO server deployment, Object Lock, replication, billing APIs, universal versioning/lifecycle management, and atomic website/container migration to S3 are not available in this release. Do not treat any of these as an independent backup system.

## S3 connection form, field by field

Open **S3 Storage** and select **New connection**. The first step selects the provider; saving the second step creates the connection. The connection display name is an ARG-only label such as `Production backup archive`, not a bucket name. The optional existing Bucket field attaches a bucket immediately; leave it blank if you will choose a bucket later.

| Field | Enter | Where to get it / example |
|---|---|---|
| Provider | The service that actually stores the objects | AWS, R2, ArvanCloud, ParsPack, Backblaze B2, DigitalOcean Spaces, Wasabi, MinIO, or Generic |
| Display name | A recognizable internal label | `Nightly VPS backup`; does not change remote Object keys |
| Existing Bucket | Exact bucket already created with the provider | `backup-prod-01`; lowercase letters, digits, and hyphens are safest |
| Endpoint URL | HTTPS origin for that account/region | No bucket name, path, query, or credentials; R2 example: `https://<ACCOUNT_ID>.r2.cloudflarestorage.com` |
| Region / Signing Region | Region used to sign requests | Copy from the provider's connection details; do not infer it from the host name |
| Addressing Style | How the bucket is represented in requests | Start with `Auto`; try `Path-style` if custom TLS/bucket DNS fails |
| Access Key ID | Programmatic key identifier | Access Keys, API Keys, or Application Keys page; usually visible later |
| Secret Access Key | Secret half of the key pair | Copy at creation time; ARG does not reveal it again |
| Session Token | Short-lived token when using temporary credentials | Enter only if the provider issued it with that key pair; observe its expiry |
| Private endpoint | Allow a MinIO or trusted internal destination | Requires explicit confirmation; sensitive metadata destinations remain blocked |

Keep LTR values free of leading/trailing spaces. The endpoint must be an HTTPS origin; do not enter `s3.region.example.net/bucket`. Bucket has a separate field. For AWS, leave Endpoint empty so the SDK selects AWS's endpoint. For other providers, enter only the service endpoint. Region is the request-signing region, not the ARG server's country.

### Create a least-privilege key

Use a read-only key if ARG only needs to browse/download. Copying VPS files to a bucket requires Put/Write; deleting Objects requires Delete. Listing all account buckets may require an additional permission. If a key is scoped to one bucket, enter that known bucket manually and test it; lack of ListBuckets does not automatically mean the credentials are invalid. Avoid granting bucket administration to a routine file-transfer key unless ARG must create buckets.

Secrets cannot be read back from ARG after saving. To rotate, open connection settings and enter the replacement Access Key ID and Secret; leaving credential fields blank while editing keeps the stored key. Create the new key at the provider, test it in ARG, then revoke the old key. This minimizes downtime.

## How to obtain values from every supported provider

Provider console labels can change with account type or UI localization. The menu paths below name the relevant areas; use the linked official provider documentation for the current details. ARG cannot purchase a service or issue a provider key on your behalf.

### Amazon S3

1. In AWS Console, open **S3 → Buckets**. Create a bucket in the intended region or select an existing one. Copy the region shown in bucket properties, e.g. `eu-central-1`; this is ARG's Region.
2. Open **IAM → Users** and create a dedicated ARG identity (or use an appropriately scoped role). Restrict its policy to the bucket/prefix and required actions: `ListBucket` and `GetObject` for browsing/downloading, `PutObject` for uploads, and `DeleteObject` only if ARG must delete.
3. Under the identity's **Security credentials → Access keys**, create a key when permitted. Copy Access Key ID and Secret Access Key immediately; save the secret in a password manager.
4. Select **Amazon S3** in ARG, leave Endpoint blank, enter the AWS region exactly, and provide the key pair. Test the connection.
5. Use temporary role credentials only if the current ARG/backend credential flow supports them. Access, secret, and session token must belong to the same session.

Example: Bucket=`arg-nightly-eu`, Region=`eu-central-1`, empty Endpoint, Addressing=`Auto`. For `AccessDenied`, review the bucket/prefix policy and required operations instead of randomly changing regions.

### Cloudflare R2

1. In Cloudflare Dashboard, open **Storage & databases → R2 → Overview**. Enable R2 if necessary and create the bucket with **Create bucket**.
2. Copy the **Account ID** from Account Details. The standard endpoint is `https://<ACCOUNT_ID>.r2.cloudflarestorage.com`; substitute your ID. Buckets created in a specific jurisdiction require that jurisdiction's endpoint instead.
3. Go to **R2 → Manage API Tokens → Create Account API token** or User API token. Choose **Object Read & Write** scoped to only the target bucket, or Read for a read-only use case. R2 may need to be enabled/available before credentials can be created.
4. Copy **Access Key ID** and **Secret Access Key** from the result immediately; the secret is not shown again. Confirm the endpoint on that page or R2 Overview.
5. In ARG choose **Cloudflare R2**, enter the endpoint, set Region to `auto`, enter the exact bucket and key pair, then test.

`auto` is the signing region required for R2's S3 compatibility. It is not derived from the server's IP. R2 does not implement every AWS API; a capability marked unsupported cannot be fixed by changing the region.

### ArvanCloud Object Storage

1. Open **Cloud Storage** in ArvanCloud's panel and identify the service/region where the bucket lives. Create/select the bucket there. ARG's ArvanCloud preset does not advertise bucket creation.
2. The official Arvan SDK guide says S3 `access_key` and `secret_key` are available in the Cloud Storage dashboard. These S3 keys are not the same as an Arvan Machine User/API management key; do not paste the management API token into the S3 form.
3. Confirm the regional endpoint from the bucket page. ARG presets include Iran Central 1: `https://s3.ir-central1.arvanstorage.ir`; Simin: `https://s3.ir-thr-at1.arvanstorage.ir`; Shahriar: `https://s3.ir-tbz-sh1.arvanstorage.ir`. If the account panel shows a different endpoint, choose Custom and use the panel's value.
4. **Signing Region** is the S3 request-signing region and is not the endpoint hostname. Use the region in that service's connection details or SDK docs. For Iran Central 1 the preset proposes `ir-central1`. If the signing region for Simin/Shahriar is not explicitly shown, obtain it from the official guide or provider support; do not guess `ir-thr-at1` or `ir-tbz-sh1` from the host.
5. Copy the bucket's exact name and create a bucket-scoped S3 key where the provider allows it.

Example: Provider=`ArvanCloud`, region Iran Central 1, Endpoint=`https://s3.ir-central1.arvanstorage.ir`, Region=`ir-central1`, Bucket=`arg-backups`, keys from the Cloud Storage dashboard. On `SignatureDoesNotMatch`, check signing region and VPS clock; do not substitute the Machine User key.

### ParsPack Cloud Storage

1. Sign in to ParsPack and open **Cloud Storage**. Create or select a bucket there; ARG does not purchase storage or create a bucket for this preset.
2. The official docs link to **Dashboard and access management** and **How to connect to Cloud Storage**. In the service panel, open connection/access details and copy the S3/REST Endpoint, Access Key, and Secret Key. The endpoint is specific to the service/account; do not use an invented global default.
3. Save a newly displayed Secret immediately. A bucket-scoped key may not have ListBuckets permission; copy the bucket name from the same service page and enter it manually in ARG.
4. Choose **ParsPack** in ARG. Paste the endpoint as documented, including `https://` if the endpoint's TLS connection supports it. Fill Region only if the account's connection details provide one; ARG intentionally does not invent a ParsPack region. Enter the key pair and bucket, then test.

If the panel copies a hostname without a scheme, add `https://` only when the account's official connection documentation confirms TLS for it. A 403 is usually a scope/permission or bucket-name issue; changing the key will not fix DNS/TLS errors.

### Backblaze B2 (S3-Compatible)

1. Ensure B2 Cloud Storage is active in Backblaze Web Console. Open **B2 Cloud Storage → Buckets**, create/select the bucket, and note its endpoint and region from bucket details.
2. Under **B2 Cloud Storage → Application Keys → Add a New Application Key**, create a standard application key; do not use the account master key with the S3-compatible API. Restrict it to the bucket and choose Read/Write or Read Only as needed. Listing all buckets requires the additional `List all bucket names` capability; for least privilege, enter a known bucket manually.
3. Map Key ID to ARG's Access Key ID and Application Key to Secret Access Key. The Application Key is shown only once.
4. The endpoint pattern is `https://s3.<region>.backblazeb2.com`; if bucket details say `us-west-004`, use `https://s3.us-west-004.backblazeb2.com` and Region=`us-west-004`, not an unrelated AWS region.
5. Select **Backblaze B2** in ARG and enter endpoint, region, bucket, and credentials. Deleting Objects may require both `writeFiles` and `deleteFiles` capabilities.

### DigitalOcean Spaces

1. In the Control Panel open **Spaces Object Storage → Buckets** and select the bucket. Its Overview shows the origin endpoint, typically `<region>.digitaloceanspaces.com`, for example `nyc3.digitaloceanspaces.com`. Use that exact region.
2. Open **Spaces Object Storage → Access Keys → Create Access Key**. Where available, restrict it to the bucket and only Read or Read/Write permissions needed. Copy Access Key ID and Secret at creation time; the secret cannot be retrieved later.
3. In ARG enter the regional hostname with `https://`, e.g. `https://nyc3.digitaloceanspaces.com`, Region=`nyc3`, then the bucket and key pair.

Do not append the bucket name to Endpoint. If a bucket name contains dots and TLS/virtual-host addressing fails, try `Path-style`. Key scope is subject to current Spaces feature and policy limits.

### Wasabi

1. In Wasabi Console verify the service and bucket, then copy the bucket's region.
2. Go to **Access Keys → Create Access Key** and choose the main or a sub-user. Prefer a dedicated user and least privilege if available. Wasabi documents at most two simultaneous keys per user, so plan rotation around that limit.
3. Choose the matching regional endpoint. For US East 1, examples are `https://s3.wasabisys.com` or `https://s3.us-east-1.wasabisys.com`; use the official regional service URL table for other regions.
4. Enter Region exactly as shown by the console/provider documentation, then the bucket and Access/Secret key pair in ARG.

Do not use the US East endpoint for a bucket in another region. If DNS/TLS works but the signature fails, verify the endpoint/region pair first.

### MinIO

Run MinIO on your VPS or trusted network, then create a bucket and a dedicated Service Account/Access Key through MinIO Console or `mc`. Avoid using the MinIO root/admin credentials for routine ARG access. Endpoint is the HTTPS S3 API address, e.g. `https://minio.example.net:9000` or a trusted private endpoint such as `https://10.0.0.8:9000`.

For a private endpoint, enable **Private/internal endpoint** in ARG and confirm it. Enter only a destination you control. MinIO's Console and S3 API may use different ports; the S3 endpoint must point to the API port, not the Console page. Set Region to the MinIO server configuration. If no custom region is configured, follow that deployment's documented/default setting rather than guessing. Start with `Auto`; `Path-style` can be more compatible on private networks without wildcard DNS.

### Generic S3-Compatible / Custom

Use this preset when the service is not listed or supplies a custom compatible endpoint. Obtain **S3 endpoint**, **signing region**, **bucket**, **Access Key ID**, **Secret Access Key**, and **Session Token** if temporary credentials are used. Confirm which List/Get/Put/Delete permissions the key has and whether account bucket listing is enabled. Enter an HTTPS endpoint origin without a path; take Region from the provider's own documentation. Choose `Path-style` if that service requires it.

## How to interpret Test connection

**Check connection** makes actual requests and writes or updates the `arg-verify` marker Object in the selected bucket, reads it back, and leaves it there. Do not delete this marker unless you no longer need the test record. This verifies the tested operations only; it does not prove every S3 API or a full file migration will work.

| Result | Meaning and next step |
|---|---|
| Endpoint/DNS/TLS failure | Check host, scheme, DNS, TLS clock, outbound 443, and endpoint certificate |
| Credential/signature failure | Use the matching Access/Secret pair; check whitespace, signing region, VPS clock, and addressing style |
| Bucket listing denied | The key may intentionally be scoped; enter the known bucket manually and test it |
| `arg-verify` write denied | Correct PutObject or prefix permission; a read-only key cannot pass a write test |
| Write works, read fails | Check GetObject/HeadObject permission or provider API compatibility |
| Test succeeds | The tested operations work for this bucket; this does not prove Delete, CreateBucket, ACL, or Lifecycle permissions |

## Rotate credentials without downtime

1. Create a replacement key in the provider console; do not revoke the old one yet.
2. Edit the ARG connection and enter the replacement ID and Secret. Empty credential fields while editing preserve the existing key.
3. Save and run the `arg-verify` connection test.
4. If successful, check mounts/transfers using this connection, then revoke the old provider key.
5. If it fails, keep the old key active and fix endpoint, permission, or region before retrying.

## Limits to understand before operating

- Adding or deleting a connection in ARG does not create or delete the provider bucket or its Objects. Real bucket deletion is a separate destructive operation and is not universally supported.
- S3 has no POSIX folders; displayed folders are prefixes. Rename is usually Copy+Delete and can be interrupted partway through.
- A read-only key is suitable for browsing/downloading; VPS-to-bucket transfer needs write access. Read-only is the recommended initial mount mode.
- Bucket listing, CreateBucket, policies, versioning, ACL, and lifecycle vary by provider. An unsupported capability does not invalidate the entire connection.
- Usage scanning paginates through Objects and can take time/API requests for large buckets. Results are cached up to 24 hours. Never read `failed` as zero.
- A cloud mount does not add physical VPS disk capacity. Rclone's local cache consumes VPS disk.
- Directory transfer creates multiple Objects. On interruption, inspect per-operation results, keep the source, and verify destination Objects before retrying.

## Findings closed or reduced

| ID | Earlier risk | Recheck result | Evidence / tests | Residual limitation |
|---|---|---|---|---|
| S3-004 | DNS could change after validation and before the S3 client connected | **Fixed in code.** Custom S3 requests use a loopback-only CONNECT proxy. The endpoint is resolved and every answer is checked; the proxy connects to those exact IPs while TLS still validates the configured hostname. Redirects are not used by the tunnel. Each exact validated host/port/address/policy set gets a process-keyed HMAC capability, so another connection's DNS result cannot replace it and repeated use of the same result does not consume another target slot. Proxy target answers are capped at 16 addresses and connection attempts share a 10-second deadline. | `custom_endpoint_resolution_returns_exact_validated_addresses`, `pinned_s3_proxy_uses_validated_ip_and_rejects_authority_changes`, `pinned_proxy_tokens_are_unique_for_the_same_host_with_different_resolutions`, and `custom_endpoint_list_bucket_xml_parses_names_and_rejects_malformed_responses`. | No live AWS/ArvanCloud/ParsPack/R2/MinIO interoperability run. The local tunnel fixture proves routing and authority checks, not provider-specific signing or compatibility.
| S3-005 | Explicit private-endpoint opt-in also admitted loopback/link-local and special-use targets | **Fixed in code.** Opt-in is now limited to RFC1918 IPv4 and ULA IPv6. Loopback, mapped-loopback, link-local, cloud metadata, CGNAT, documentation, and other non-public/non-private ranges are rejected even when private endpoints are enabled. | `custom_endpoint_resolution_returns_exact_validated_addresses` checks private RFC1918/ULA acceptance, loopback/mapped-loopback, link-local, metadata, CGNAT, reserved-range rejection, and the 16-address cap. | Self-hosted object stores must use an RFC1918/ULA address reachable from the VPS; loopback endpoints are intentionally unsupported to maintain the SSRF boundary.
| FILE-002 | A privileged mutation could follow a path or symlink swapped after validation | **Fixed for mutations and archives in this scope.** Directory components are opened from `/` with `openat(O_NOFOLLOW)`; file operations use anchored descriptors and `*at` syscalls. Save uses the already-validated parent descriptor and atomic exchange with inode verification. | `anchored_file_operation_keeps_the_open_directory_when_the_path_is_swapped`, `anchored_recursive_delete_removes_a_symlink_without_touching_its_target`, `atomic_editor_replacement_does_not_follow_a_symlink_target`, plus ZIP create/extract tests. | Read-only listing and disk-usage scans retain their canonical-path flow. They do not mutate targets. This is not a filesystem sandbox: authenticated administrators retain the product's existing broad file-management authority.
| FILE-003 | File copy/archive operations could consume all remaining filesystem space | **Mitigated.** Copy, cross-device move, ZIP creation, and ZIP extraction check destination free space before each file and retain a 64 MiB reserve. | `file_copy_preserves_the_free_space_reserve`; copy and archive tests. | No bounded-filesystem integration test was available. Concurrent unrelated writers can still consume space after preflight; partial outputs are removed on detected failure where cleanup is implemented.
| FED-002 | Repeated workspace renewal could accumulate valid grants/session rows and retries could strand a controller | **Fixed.** Renewal is serialized in an immediate transaction, an old-token retry returns the same derived token, expired idempotent results have their expiry renewed, superseded proxy/session rows are removed, and the older no-body protocol replaces its previous grant instead of accumulating rows. | `workspace_renewal_retry_returns_the_same_session_without_duplicate_rows` covers retry, expired retry recovery, and bounded legacy rows. | Two-panel network/restart behavior was not exercised. Legacy no-body retries can produce a different new token if the response was lost, but the previous grant is revoked and the next response remains usable; no stale valid grants accumulate.
| PERF-003 | Distinct applications could enqueue an unbounded deployment backlog | **Fixed.** At most 64 jobs may be in `queued`; an immediate SQLite transaction serializes admission, over-cap requests receive HTTP 429, and an uploaded archive is removed on rejection. One currently running job is not counted against the queue cap. | `deployment_queue_rejects_jobs_after_global_limit_without_partial_records`. | The cap is a deliberate per-process product bound; deployment load and operator workflow still need VPS measurement.
| UI-003 | Shared frontend requests could remain pending forever or be cut off by one unsafe global timeout | **Fixed in the shared JSON wrapper.** Calls now have AbortController deadlines, propagate caller cancellation, clean up listeners/timers, classify ordinary reads, polling, transfers, backups, SSL, package/runtime, MySQL, firewall, and maintenance operations separately, and preserve backend HTTP errors. | `request-policy.test.mjs`; `npm run check`; `npm run test:offline`. | Direct `fetch` paths outside the shared wrapper were not all migrated. Async job progress remains short-lived polling and must continue to use its persistent Job API.
| DB-003 | Startup migration interruption and retry behavior lacked sequence-level failure injection | **Partially mitigated.** The migration sequence is now testable at module boundaries and a test interrupts after each module, reruns all migrations twice, and checks preserved users plus the new Federation column. | `startup_migration_sequence_recovers_after_module_boundary_interruption`; module idempotency tests; full Rust suite. | No central schema-version ledger was introduced. The test does not inject a crash between individual SQL statements inside every module migration or run against a production-era database image; retain as a constrained integration risk.

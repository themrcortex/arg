## نصب سریع

نصب‌کنندهٔ مستقل را مستقیم روی سرور دریافت و اجرا کنید؛ نیازی به clone کردن مخزن نیست.

**[⬇ دریافت مستقیم install.sh](https://github.com/parsasajjadi2008/donatello/releases/latest/download/install.sh)**

```bash
curl --proto '=https' --tlsv1.2 -fsSL \
  https://raw.githubusercontent.com/parsasajjadi2008/donatello/main/install.sh \
  -o donatello.sh
sudo bash donatello.sh install
```

برای بازکردن منوی نصب و مدیریت به‌جای نصب مستقیم، آرگومان `install` را حذف کنید:

```bash
sudo bash donatello.sh
```

پس از نصب، Donatello با systemd اجرا می‌شود. برای دیدن وضعیت یا بازکردن منوی مدیریت:

```bash
sudo donatello status
sudo donatello
```

در نصب اولیه، IP عمومی سرور برای تأیید نمایش داده می‌شود. سپس می‌توانید همان IP یا دامنهٔ متصل به سرور را برای راه‌اندازی HTTPS انتخاب کنید. نصب‌کننده تلاش می‌کند گواهی Let's Encrypt را خودکار دریافت کند. برای دسترسی عمومی، پورت پنل و پورت ۸۰ جهت اعتبارسنجی گواهی باید در فایروال سرور و فایروال ارائه‌دهنده باز باشند.

> نصب خودکار برای Debian و Ubuntu دارای systemd طراحی شده و برای دریافت وابستگی‌ها و build به اینترنت نیاز دارد.

هنگام کامپایل، نصب‌کننده نشانگر زنده و زمان سپری‌شده را نمایش می‌دهد. اگر build خطا کند، خروجی کامل کامپایلر برای عیب‌یابی چاپ می‌شود.

## آشنایی با پنل

پس از نصب و راه‌اندازی HTTPS، نشانی پنل در خروجی نصب‌کننده و منوی `donatello` نمایش داده می‌شود. پنل به‌طور پیش‌فرض روی پورت `8282` در دسترس است؛ هنگام فعال‌بودن TLS، نصب‌کننده پورت امن آزاد را تنظیم می‌کند. برای تغییر پورت از منوی مدیریت یا دستور زیر استفاده کنید:

```bash
sudo donatello manage port
```

### ساخت نخستین حساب مدیر

ساخت مدیر اول از یکی از این دو روش انجام می‌شود:

1. **از طریق HTTPS عمومی:** در صفحهٔ راه‌اندازی، کد یک‌بارمصرفی را وارد کنید که نصب‌کننده روی سرور نشان می‌دهد. در منوی `donatello` نیز گزینهٔ دریافت کد راه‌اندازی وجود دارد؛ این گزینه فقط تا پیش از ساخت اولین مدیر فعال است.
2. **از طریق SSH tunnel:** اگر HTTPS هنوز آماده نیست، روی رایانهٔ خود tunnel بسازید و صفحهٔ محلی را باز کنید:

```bash
ssh -N -L 8282:127.0.0.1:8282 <SSH_USER>@<SERVER_IP>
```

سپس به [http://127.0.0.1:8282](http://127.0.0.1:8282) بروید. جای `<SSH_USER>` و `<SERVER_IP>` را با نام کاربری SSH و IP سرور خود عوض کنید. tunnel را تا پایان ساخت حساب باز نگه دارید.

برای فعال‌کردن HTTPS پس از نصب نیز اجرا کنید:

```bash
sudo donatello ssl
```

اگر سرویس systemd دیگری پورت ۸۰ را گرفته باشد، نصب‌کننده برای صدور گواهی آن را موقتاً متوقف می‌کند و پس از پایان کار دوباره راه می‌اندازد. همین روال برای تمدید خودکار گواهی نیز تنظیم می‌شود. گواهی IP در Let's Encrypt کوتاه‌عمر است و به‌صورت خودکار تمدید می‌شود. اگر پورت HTTPS پیش‌فرض در دسترس نباشد، Donatello پورت آزاد دیگری انتخاب می‌کند؛ بازبودن آن پورت در فایروال ارائه‌دهنده را هم بررسی کنید.

## مدیریت با دستور `donatello`

اجرای دستور بدون آرگومان، منوی تعاملی را باز می‌کند. با کلیدهای بالا و پایین حرکت کنید و گزینه را با Enter اجرا کنید. منو هنگام اجرا وضعیت سرویس، نشانی پنل و وضعیت نسخه را بررسی می‌کند.

| دستور | کار |
| --- | --- |
| `sudo donatello` | منوی کامل مدیریت |
| `sudo donatello status` | وضعیت سرویس |
| `sudo donatello start` | شروع سرویس |
| `sudo donatello stop` | توقف سرویس |
| `sudo donatello restart` | راه‌اندازی مجدد سرویس |
| `sudo donatello logs` | نمایش گزارش‌های اخیر |
| `sudo donatello logs 300` | نمایش تعداد دلخواه خط از گزارش |
| `sudo donatello manage port` | تغییر پورت پنل |
| `sudo donatello ssl` | راه‌اندازی HTTPS و گواهی |
| `sudo donatello update` | دریافت نسخهٔ تازه و به‌روزرسانی |
| `sudo donatello password` | بازنشانی رمز حساب با دسترسی root |
| `sudo donatello delete` | حذف برنامه و سرویس با امکان نگه‌داشتن داده‌ها |
| `sudo donatello delete --purge` | حذف برنامه، تنظیمات و داده‌ها |

گزینهٔ حذف کامل برای تأیید، عبارت مشخصی را از شما می‌گیرد. پیش از پاک‌کردن داده‌ها از پایگاه‌دادهٔ خود نسخهٔ پشتیبان تهیه کنید.

## سرویس، تنظیمات و داده‌ها

Donatello به‌عنوان سرویس `donatello.service` نصب می‌شود و با راه‌اندازی سرور به‌صورت خودکار اجرا خواهد شد.

```bash
systemctl status donatello
journalctl -u donatello -f
```

| مسیر | محتوا |
| --- | --- |
| `/etc/donatello/donatello.env` | تنظیمات اجرای سرویس |
| `/var/lib/donatello` | پایگاه‌داده و داده‌های برنامه |

## پیش‌نیازها

- Debian یا Ubuntu با `systemd`
- دسترسی `root` یا `sudo`
- اتصال اینترنت هنگام نصب و build
- پورت پنل و در صورت فعال‌سازی HTTPS، پورت‌های لازم در فایروال سرور و ارائه‌دهنده

## توسعه

برای build محلی به Rust stable و Node.js 20 یا جدیدتر نیاز دارید. مراحل را جداگانه اجرا کنید تا خروجی هر بخش روشن باشد:

```bash
git clone https://github.com/parsasajjadi2008/donatello.git
cd donatello
```

### ۱. آماده‌سازی رابط وب

```bash
cd frontend
npm ci
npm run build
cd ..
```

### ۲. اجرای بک‌اند Rust

```bash
cargo run
```

برای کامپایل نسخهٔ بهینه‌شده به‌جای اجرای توسعه:

```bash
cargo build --locked --release
```

### توسعهٔ فرانت‌اند

برای اجرای رابط در حالت توسعه، از پوشهٔ `frontend` اجرا کنید:

```bash
cd frontend
npm run dev
```

فرانت‌اند پس از build در `frontend/dist` قرار می‌گیرد و هنگام build در باینری Rust جاسازی می‌شود. بعد از هر تغییر در رابط، پیش از build بک‌اند `npm run build` را اجرا کنید.

```text
src/main.rs                  API، نشست‌ها و خواندن اطلاعات Linux
install.sh                   نصب، سرویس systemd، به‌روزرسانی و حذف
frontend/src/App.tsx         پوستهٔ پنل، ورود و ساخت مدیر
frontend/src/pages.tsx       صفحات داشبورد و مدیریت
frontend/src/components/ui   کامپوننت‌های رابط کاربری
PLAN.md                      نقشهٔ راه قابلیت‌ها
```

## محدودیت‌های فعلی و نقشهٔ راه

نسخهٔ فعلی وضعیت UFW را **نمایش می‌دهد** و از پنل وب قانون فایروال را تغییر نمی‌دهد. پایش شبکه شامل آمار کلی هر رابط و فهرست پورت‌های شنونده است؛ شمارش بایت به‌ازای هر پورت، ترمینال وب، Speedtest و مدیریت سرویس‌های دیگر از داخل پنل در حال حاضر ارائه نشده‌اند. وضعیت این موارد و برنامهٔ توسعه در [PLAN.md](PLAN.md) آمده است.
